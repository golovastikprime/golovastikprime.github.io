Семестр 2 · Контест 1

Задача F — Цветной рюкзак

Accepted · C++ · 27 июля 2026

Группировка предметов по цветам устраняет экспоненциальную маску и превращает задачу в group knapsack с одним слоем DP на каждый цвет.

Результат

Статус

Accepted. Решение использует динамическое программирование по цветовым группам и хранит только два слоя по вместимости.

  • время: \(O(nm)\);
  • память DP: \(O(m)\);
  • полная память: \(O(n+m)\).

Условие

Краткое условие

Даны \(n\) предметов. У предмета \(x\) известны вес \(w_x\), стоимость \(c_x\) и цвет \(f_x\). Нужно выбрать набор суммарного веса не более \(m\), в котором цвета попарно различны, и максимизировать

\[ \sum_{x\in S}c_x \qquad\text{при}\qquad \sum_{x\in S}w_x\le m. \]

Ограничения:

\[ 1\le g\le n\le300, \qquad 1\le m\le10^4. \]

Неудачная идея

Почему маска цветов не подходит

Первоначальное состояние имело вид

\[ F(k,s,b), \]

где \(k\) — число обработанных предметов, \(s\) — вместимость, а \(b\) — маска использованных цветов. Состояние корректно хранит ограничение, но даёт \(2^g\) масок и сложность порядка

\[ O(nm2^g), \]

что неприемлемо при \(g\le300\). Маска нужна лишь пока в будущем может встретиться предмет уже использованного цвета. Значит, менять следует не состояние, а порядок обработки.

Подход

Один цвет — один этап DP

Разобьём предметы на классы одинакового цвета:

\[ x\sim y \quad\Longleftrightarrow\quad f_x=f_y, \qquad C_1,\ldots,C_g. \]

Если обработать сразу весь класс \(C_t\), к этому цвету больше не придётся возвращаться. Поэтому цвет становится этапом динамики, а маска исчезает.

Это частный случай group knapsack, или multiple-choice knapsack: из каждой группы разрешено выбрать не более одного элемента.

Динамика

Состояние и переход

Определим \(dp[t][s]\) как максимальную стоимость набора из первых \(t\) цветовых классов с суммарным весом не более \(s\).

База

\[ dp[0][s]=0 \qquad \text{для всех }0\le s\le m. \]

До обработки цветов доступен только пустой набор.

Переход

Для очередного класса можно не брать ничего либо выбрать ровно один предмет:

\[ \boxed{ dp[t][s] = \max\left( dp[t-1][s], \max_{\substack{x\in C_t\\w_x\le s}} \left(dp[t-1][s-w_x]+c_x\right) \right) }. \]

Все кандидаты читаются исключительно из слоя \(t-1\). Если использовать уже обновлённые значения слоя \(t\), один цвет можно будет выбрать несколько раз.

Ответ

\[ \boxed{dp[g][m]}. \]

Доказательство

Корректность перехода

Докажем по индукции по \(t\), что \(dp[t][s]\) равно оптимальной стоимости допустимого набора из первых \(t\) классов веса не более \(s\).

База

При \(t=0\) единственный допустимый набор пуст, поэтому его стоимость равна нулю для любой вместимости.

Индукционный переход

Рассмотрим оптимальный набор для первых \(t\) классов.

  • Если из \(C_t\) ничего не выбрано, его стоимость не превосходит \(dp[t-1][s]\).
  • Если выбран предмет \(x\in C_t\), после его удаления остаётся допустимый набор из предыдущих классов веса не более \(s-w_x\). Его стоимость не превосходит \(dp[t-1][s-w_x]\).

Переход перебирает оба случая и все допустимые предметы текущего цвета. Обратно, каждый его кандидат задаёт допустимый набор: решение предыдущих классов либо остаётся без изменения, либо дополняется одним предметом нового цвета. Значит, переход не пропускает оптимум и не создаёт недопустимых решений.

Оптимизация

Два слоя памяти

Слой \(dp[t]\) зависит только от \(dp[t-1]\), поэтому достаточно двух массивов:

  • prev[s] — ответ после уже обработанных цветов;
  • cur[s] — ответ после добавления текущего цвета.

Сначала весь массив cur вычисляется только из prev, затем один раз выполняется

std::swap(prev, cur);

Граница слоя проходит по цветовому классу, а не по предмету или вместимости.

Реализация

Accepted-код

#include <algorithm>
#include <iostream>
#include <utility>
#include <vector>

struct Item {
  int cost;
  int weight;
};

int main() {
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);
  std::cout.tie(nullptr);

  int n;
  int g;
  int m;
  std::cin >> n >> g >> m;

  std::vector<std::vector<Item>> classes(g);
  for (int i = 0; i < n; ++i) {
    int weight;
    int cost;
    int color;
    std::cin >> weight >> cost >> color;
    classes[color - 1].push_back({cost, weight});
  }

  std::vector<int> prev(m + 1, 0);
  std::vector<int> cur(m + 1, 0);

  for (const auto& color_class : classes) {
    for (int capacity = 0; capacity <= m; ++capacity) {
      cur[capacity] = prev[capacity];

      for (const Item& item : color_class) {
        if (item.weight <= capacity) {
          cur[capacity] =
              std::max(cur[capacity],
                       prev[capacity - item.weight] + item.cost);
        }
      }
    }

    std::swap(prev, cur);
  }

  std::cout << prev[m];
}

Оценка

Сложность

Для каждого класса перебираются все вместимости и все предметы этого класса:

\[ \sum_{t=1}^{g}O\bigl(m(1+|C_t|)\bigr) =O(gm)+O\left(m\sum_{t=1}^{g}|C_t|\right). \]

Поскольку \(\sum|C_t|=n\) и \(g\le n\), получаем

\[ \boxed{T(n,m)=O(nm)}. \]

Два слоя DP занимают \(O(m)\), а хранение предметов по классам — \(O(n+g)\):

\[ \boxed{M(n,m)=O(n+g+m)=O(n+m)}. \]

Переполнение int невозможно при указанных ограничениях: из \(c_i\le w_i\) следует \(\sum c_i\le\sum w_i\le m\le10^4\).

Разбор ошибок

Failure modes

  1. Экспоненциальная маска цветов. Ограничение хранилось явно, хотя его можно устранить порядком обработки. Исправление — объединить предметы одного цвета и сделать класс этапом DP.
  2. Потерянная стоимость. В переходе использовалось \(dp[t-1][s-w_x]\) без слагаемого \(c_x\). На одном предмете веса и стоимости \(1\) это даёт ноль вместо единицы.
  3. Перепутанные cost и weight. Structured binding не соответствовал порядку полей структуры. Явные обращения item.weight и item.cost устраняют зависимость от порядка полей.
  4. Неверный порядок циклов и ранний swap. Обновлённое значение могло повторно использоваться внутри того же цвета. Новый слой нужно полностью вычислить из старого, а массивы менять местами только после завершения класса.

Самопроверка

Инвариант реализации

prev[s] хранит оптимальную стоимость допустимого набора из всех уже обработанных цветовых классов с суммарным весом не более s.

Во время обработки класса все чтения идут из prev, поэтому кандидат ещё не содержит предмет текущего цвета. Добавление одного item сохраняет ограничение «не более одного предмета каждого цвета». После вычисления всего cur и обмена массивов инвариант выполняется уже для расширенного множества классов.

Перенос идеи

Как распознать group knapsack

  • объекты разбиты на независимые группы;
  • из каждой группы разрешено выбрать не более одного объекта;
  • есть общее ограничение на сумму весов;
  • целевая функция складывает стоимости;
  • вместимость достаточно мала для DP по весу.

Полезный вопрос:

Можно ли выбрать порядок обработки, после которого уже обработанное ограничение больше никогда не придётся проверять явно?

Битовая маска здесь экспоненциальна. Обычный 0/1-рюкзак запрещает повтор одного предмета, но позволяет взять два разных предмета одного цвета. Жадный выбор лучшего предмета каждого цвета не учитывает сочетания весов между группами.

Вывод

Итоговый шаблон

\[ \text{предметы} \Longrightarrow \text{классы одинакового цвета} \Longrightarrow \text{один слой DP на один класс}. \]

Главная идея — не усложнять состояние, а изменить порядок обработки. Это устраняет множество использованных цветов из состояния и сводит задачу к \(O(nm)\) времени и \(O(m)\) памяти для динамики.
