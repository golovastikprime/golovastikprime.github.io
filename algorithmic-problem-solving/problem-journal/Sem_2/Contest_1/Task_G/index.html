Семестр 2 · Контест 1

Задача G — Множества враждующих чисел

Accepted · C++ · 28 июля 2026

Фиксация максимального элемента превращает попарное ограничение в верхнюю границу для остатка, а префиксное состояние ускоряет подсчёт с кубического до квадратичного времени.

Результат

Статус

Accepted. Решение использует динамическое программирование по сумме и верхней границе максимального элемента.

  • время: \(\Theta(n^2)\);
  • память: \(\Theta(n^2)\);
  • тип значений: long long.

Условие

Математическая формулировка

Для натуральных чисел \(a<b\)

\[ a,b\text{ дружат} \iff b<2a, \qquad a,b\text{ враждуют} \iff b\ge2a. \]

Нужно посчитать множества \(A\), в которых любые два различных элемента враждуют, а сумма равна заданному \(n\):

\[ \sum_{a\in A}a=n, \qquad 1\le n\le2000. \]

Наблюдение

Достаточно соседних элементов

Пусть элементы множества упорядочены:

\[ m_1<m_2<\dots<m_k. \]

Попарная вражда равносильна системе

\[ \boxed{m_{i+1}\ge2m_i} \qquad (1\le i<k). \]

Необходимость очевидна для соседних пар. Обратно, при \(i<j\) имеем \(m_j\ge m_{i+1}\ge2m_i\), поэтому любая пара тоже враждует.

Если максимум множества равен \(y\), после его удаления все оставшиеся элементы не превосходят

\[ \left\lfloor\frac y2\right\rfloor. \]

Получается задача того же вида, но с меньшей суммой.

Первое состояние

Подсчёт по точному максимуму

Определим

\[ f(y,s) = \#\left\{ A: \sum_{a\in A}a=s,\ \max A=y,\ A\text{ допустимо} \right\}. \]

После удаления максимума \(y\) максимум остатка должен быть не больше \(\lfloor y/2\rfloor\). Поэтому

\[ f(y,s)= \begin{cases} 0, &s<y,\\[2mm] 1, &s=y,\\[2mm] \displaystyle \sum_{x=1}^{\lfloor y/2\rfloor}f(x,s-y), &s>y. \end{cases} \]

Случай \(s=y\) соответствует множеству \(\{y\}\). Ответ можно записать как

\[ \operatorname{Answer}(n) = \sum_{y=1}^{n}f(y,n). \]

Прямое суммирование перехода требует \(O(n)\) на каждое из \(O(n^2)\) состояний, то есть \(O(n^3)\) времени.

Оптимизация

Префикс по максимуму

Введём агрегированное состояние

\[ G(y,s) = \sum_{x=1}^{y}f(x,s). \]

Оно равно числу допустимых множеств суммы \(s\), максимальный элемент которых не превосходит \(y\). Именно это значение хранит dp[y][s].

Разделим множества на не содержащие \(y\) и содержащие его:

\[ \boxed{ G(y,s)=G(y-1,s)+ \begin{cases} 0, &s<y,\\[1mm] 1, &s=y,\\[1mm] G\left(\left\lfloor y/2\right\rfloor,s-y\right), &s>y. \end{cases} } \]

База и ответ:

\[ G(0,s)=0 \quad(s\ge1), \qquad \boxed{\operatorname{Answer}(n)=G(n,n)}. \]

Ограничение на максимум \(n\) ничего не исключает: элемент множества суммы \(n\) не может превосходить \(n\).

Доказательство

Биекция после удаления максимума

Для случая \(s>y\) рассмотрим отображение

\[ \Phi(A)=A\setminus\{y\}. \]

Если допустимое множество \(A\) суммы \(s\) содержит максимум \(y\), то остаток:

  • имеет сумму \(s-y\);
  • остаётся допустимым;
  • содержит только элементы не больше \(\lfloor y/2\rfloor\).

Значит, остаток учитывается в \(G(\lfloor y/2\rfloor,s-y)\).

Обратно, к любому множеству из этого состояния можно добавить \(y\). Для любого его элемента \(z\le\lfloor y/2\rfloor\), следовательно \(y\ge2z\), и новый максимум враждует со всем остатком. Добавление и удаление \(y\) взаимно обратны, поэтому переход считает множества точно.

Вычисление

Порядок заполнения

Внешний цикл проходит по сумме, внутренний — по границе максимума:

for s = 1..n:
    for y = 1..n:

Для вычисления \(G(y,s)\) нужны:

  • \(G(y-1,s)\), уже вычисленное на предыдущей итерации внутреннего цикла;
  • \(G(\lfloor y/2\rfloor,s-y)\), лежащее в строке меньшей суммы, поскольку \(s-y<s\).

Инвариант циклов

Перед обработкой суммы \(s\) корректно вычислены все \(G(y,t)\) для \(t<s\). Перед парой \((y,s)\) дополнительно готовы \(G(z,s)\) для \(z<y\). Переход читает только эти состояния и сохраняет инвариант.

Пример

Сумма 5

Для \(n=5\) подходят ровно два множества:

\[ \{5\}, \qquad \{1,4\}. \]

В паре \(\{1,4\}\) выполняется \(4\ge2\cdot1\). Множество \(\{2,3\}\) не подходит, поскольку \(3<2\cdot2\). Поэтому

\[ \operatorname{Answer}(5)=2. \]

Реализация

Accepted-код

#include <iostream>
#include <vector>

int main() {
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);
  std::cout.tie(nullptr);

  int n;
  std::cin >> n;

  std::vector<std::vector<long long>> dp(
      n + 1, std::vector<long long>(n + 1, 0));

  auto f = [&dp](int y, int s) -> long long {
    if (s == y) {
      return 1;
    }

    if (s < y) {
      return 0;
    }

    return dp[y / 2][s - y];
  };

  for (int s = 1; s <= n; ++s) {
    for (int y = 1; y <= n; ++y) {
      dp[y][s] = dp[y - 1][s] + f(y, s);
    }
  }

  std::cout << dp[n][n];
}

Тип данных

Почему нужен long long

При верхней границе входа ответ уже не помещается в 32-битный знаковый тип:

\[ \operatorname{Answer}(2000) = 3\,364\,745\,671 > 2\,147\,483\,647 = \texttt{INT\_MAX}. \]

Использование int приводит к signed integer overflow, поэтому вся таблица хранится в long long.

Оценка

Сложность

Таблица содержит \((n+1)^2\) ячеек, каждое состояние вычисляется за константное время:

\[ \boxed{T(n)=\Theta(n^2)}, \qquad \boxed{W(n)=\Theta(n^2)}. \]

При \(n=2000\) значения long long занимают примерно 32 МБ без небольших накладных расходов контейнеров.

Разбор ошибок

Ошибки и тупики

  1. Неравенство в обратную сторону. Верно \(b\ge2a\) для \(a<b\). Множество \(\{2,3\}\) опровергает условие \(2a\ge b\): оно выполняется, хотя числа дружат.
  2. Интервалы между степенями двойки. Принадлежность соседним интервалам не гарантирует вражду: \(3\in[2,4)\) и \(4\in[4,8)\), но \(4<2\cdot3\).
  3. Только двоичное разложение. Оно даёт одно представление, но не считает все множества. Для пяти кроме \(\{1,4\}\) существует \(\{5\}\).
  4. Кубический переход. Прямое суммирование по всем меньшим максимумам занимает \(O(n)\) на состояние. Префиксное \(G(y,s)\) заменяет сумму одним обращением.

Перенос идеи

Как распознать паттерн

  • у каждого подсчитываемого объекта есть единственный максимум;
  • после удаления максимума получается объект того же типа;
  • новый максимум задаёт верхнюю границу для остальных элементов;
  • переход суммирует состояния по всем допустимым максимумам;
  • эту сумму можно хранить как отдельное префиксное состояние.
\[ \text{зафиксировать максимум} \Longrightarrow \text{удалить максимум} \Longrightarrow \text{ограничить остаток} \Longrightarrow \text{ускорить сумму префиксом}. \]

Вывод

Главный итог

В состоянии нужны текущая сумма и верхняя граница максимального элемента. Удаление максимума \(y\) уменьшает сумму на \(y\) и ограничивает остаток значением \(\lfloor y/2\rfloor\). Префиксное состояние \(G(y,s)\) сразу агрегирует все возможные максимумы и снижает сложность с \(O(n^3)\) до \(\Theta(n^2)\).
