Задача C — Топологическая сортировка

Accepted · C++ · 2 августа 2026

Трёхцветный DFS одновременно обнаруживает цикл и строит времена выхода: в DAG порядок их убывания является топологическим.

Результат

Статус

Accepted. DFS с тремя цветами проверяет ацикличность и назначает вершинам времена выхода.

  • DFS: \(\Theta(n+m)\);
  • явная сортировка: \(O(n\log n)\);
  • память: \(\Theta(n+m)\).

Условие

Линейный порядок зависимостей

Дан ориентированный граф \(G=(V,E)\), где \(V=\{1,2,\ldots,n\}\), \(1\le n\le10^5\) и \(0\le m\le10^5\).

Нужно найти перестановку всех вершин \(p_1,\ldots,p_n\), в которой для каждого ребра \((u,v)\in E\)

\[ pos(u)<pos(v), \]

либо установить, что такого порядка нет. Топологический порядок существует тогда и только тогда, когда граф является DAG.

Наблюдение

Цикл и времена выхода

Если при обработке ребра \(v\to u\) вершина \(u\) находится в текущем стеке DFS, древесный путь \(u\leadsto v\) вместе с этим ребром образует цикл.

Если циклов нет, для каждого ребра \(u\to v\) конец ребра завершает работу раньше начала:

\[ \boxed{t_{out}(u)>t_{out}(v)}. \]

Следовательно, вершины по убыванию времени выхода образуют топологический порядок.

Состояния

Зачем нужны три цвета

  • 0, белая — DFS ещё не входил в вершину;
  • 1, серая — вершина находится в активном стеке;
  • 2, чёрная — вершина и исходящие рёбра полностью обработаны.

Ребро в серую вершину доказывает цикл. Ребро в чёрную вершину этого не доказывает: например, граф

\[ 1\to2, \qquad 1\to3, \qquad 3\to2 \]

ацикличен, хотя вершина \(2\) может быть посещена до обработки ребра \(3\to2\).

Постпорядок

Время выхода

Время назначается только после обработки всех исходящих рёбер:

color[v] = 2;
tout[v] = timer++;

Для минимального графа \(1\to2\) сначала завершается вершина \(2\), затем \(1\):

\[ t_{out}(2)<t_{out}(1). \]

Поэтому сортировать нужно именно по убыванию времени выхода.

Алгоритм

DFS по всем компонентам

  1. Построить списки исходящих рёбер.
  2. Запустить DFS из каждой белой вершины.
  3. При входе покрасить вершину в серый.
  4. Для белого соседа продолжить DFS, для серого сообщить о цикле, чёрного пропустить.
  5. После всех рёбер покрасить вершину в чёрный и назначить время выхода.
  6. При цикле вывести -1.
  7. Иначе вывести вершины по убыванию tout.

Инварианты

Что поддерживает обход

  • серые вершины — текущий активный путь DFS;
  • у чёрной вершины просмотрены все исходящие рёбра и назначено время выхода;
  • до очередного выхода timer равен числу завершённых вершин;
  • каждая вершина обрабатывается ровно один раз благодаря запуску только из белых вершин.

Доказательство

Корректность

Обнаружение цикла

Серая вершина является предком текущей, поэтому ребро к ней замыкает ориентированный путь. Обратно, если в графе есть цикл, рассмотрим первую его вершину, которую DFS собирается покрасить в чёрный. Её следующий сосед на цикле не может быть ни белым, ни чёрным, значит он серый и цикл будет найден.

Свойство времени выхода

Для ребра \(u\to v\) в DAG вершина \(v\) либо рекурсивно завершается до \(u\), либо уже была чёрной. Серый случай означал бы цикл. Поэтому всегда \(t_{out}(u)>t_{out}(v)\).

Топологический порядок

При сортировке по убыванию tout начало каждого ребра оказывается раньше его конца. Если же найден цикл, потребовалась бы невозможная цепочка строгих неравенств позиций, замыкающаяся сама в себя.

Пример

Один допустимый порядок

Для рёбер

\[ 1\to3, \quad2\to3, \quad3\to4, \quad2\to5, \quad5\to6 \]

одним из возможных топологических порядков является

\[ 2, 5, 6, 1, 3, 4. \]

Для цикла \(1\to2\to3\to1\) ребро \(3\to1\) ведёт в серую вершину, поэтому ответ равен -1.

Реализация

Финальный Accepted-подход

#include <algorithm>
#include <functional>
#include <iostream>
#include <vector>

struct VertexTime {
  int vertex;
  int tout;
};

int main() {
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);

  int n;
  int m;
  std::cin >> n >> m;

  std::vector<std::vector<int>> adj(n + 1);
  for (int i = 0; i < m; ++i) {
    int u;
    int v;
    std::cin >> u >> v;
    adj[u].push_back(v);
  }

  std::vector<int> color(n + 1, 0);
  std::vector<int> tout(n + 1, -1);
  int timer = 0;

  std::function<bool(int)> dfs = [&](int v) -> bool {
    color[v] = 1;

    for (int u : adj[v]) {
      if (color[u] == 0) {
        if (dfs(u)) {
          return true;
        }
      } else if (color[u] == 1) {
        return true;
      }
    }

    color[v] = 2;
    tout[v] = timer++;
    return false;
  };

  for (int v = 1; v <= n; ++v) {
    if (color[v] == 0 && dfs(v)) {
      std::cout << -1;
      return 0;
    }
  }

  std::vector<VertexTime> order;
  order.reserve(n);
  for (int v = 1; v <= n; ++v) {
    order.push_back({v, tout[v]});
  }

  std::sort(order.begin(), order.end(),
            [](const VertexTime& lhs, const VertexTime& rhs) {
              return lhs.tout > rhs.tout;
            });

  for (const auto& [vertex, exit_time] : order) {
    std::cout << vertex << ' ';
  }
}

exit_time в последнем цикле нужен только для structured binding; ответ использует поле vertex.

Оценка

Сложность

DFS обрабатывает каждую вершину и ребро постоянное число раз:

\[ \Theta(n+m). \]

В принятом подходе времена выхода затем сортируются:

\[ \boxed{T(n,m)=\Theta(n+m+n\log n)}. \]

Если добавлять вершины в массив при выходе и затем развернуть его, сортировка не нужна и время становится \(\Theta(n+m)\). Память в обоих случаях:

\[ \boxed{W(n,m)=\Theta(n+m)}. \]

Разбор кода

Неявное распространение результата

В исходном принятом фрагменте результат dfs(u) явно не проверялся. При раннем возврате вершина \(u\) оставалась серой, и родитель замечал color[u] == 1, тем самым неявно передавая сигнал вверх. Это корректно, но скрывает важный инвариант.

Финальный листинг выражает смысл напрямую:

if (color[u] == 0) {
  if (dfs(u)) {
    return true;
  }
} else if (color[u] == 1) {
  return true;
}

Также явно подключён <algorithm>, удалён неиспользуемый <unordered_set> и не хранится фиктивная вершина.

Проверки

Граничные случаи

  • одна изолированная вершина выводится как единственный элемент порядка;
  • несколько изолированных вершин допускают любую перестановку;
  • петля немедленно обнаруживается как ребро в серую вершину;
  • разные компоненты могут перемешиваться в ответе произвольным образом;
  • ребро в чёрную вершину не является циклом;
  • параллельные рёбра не нарушают алгоритм.

Разбор ошибок

Типичные неверные подходы

  1. Считать циклом любое ребро в посещённую вершину. Посещённая вершина может быть уже чёрной; нужны три состояния.
  2. Пропускать ребро в родителя. Это правило относится к неориентированному графу; здесь ребро в предка замыкает цикл.
  3. Сортировать времена по возрастанию. Это поставит конец ребра раньше начала.
  4. Запустить DFS только из вершины 1. Часть вершин и цикл в другой компоненте могут остаться незамеченными.
  5. Записать время до обработки детей. Время входа не обладает нужным свойством по всем рёбрам DAG.

Альтернатива

DFS и алгоритм Кана

DFS хранит цвета, обнаруживает цикл по ребру в серую вершину и строит reverse postorder. Алгоритм Кана хранит входные степени, обнаруживает цикл, если обработано меньше \(n\) вершин, и формирует порядок удаления вершин нулевой степени.

Оба метода работают за \(\Theta(n+m)\) без дополнительной сортировки. Алгоритм Кана с min-priority queue удобнее, если нужен лексикографически минимальный порядок.

Перенос идеи

Как распознать паттерн

  • объекты связаны направленными зависимостями;
  • для зависимости \(u\to v\) объект \(u\) должен стоять раньше;
  • цикл делает порядок невозможным;
  • нужен любой допустимый порядок.
\[ \text{направленные зависимости} \Longrightarrow \text{линейный порядок} \Longrightarrow \text{цикл означает невозможность} \Longrightarrow \text{DFS + reverse postorder}. \]

Вывод

Главный итог

DFS хранит обе необходимые части информации: серый цвет обнаруживает цикл, а момент выхода фиксирует завершение всех зависимостей из вершины. Поэтому в DAG

\[ \boxed{u\to v\implies t_{out}(u)>t_{out}(v)}, \]

и порядок убывания времён выхода является топологическим.
