Семестр 2 · Контест 3

Задача D — Компоненты сильной связности

Accepted · C++ · 2 августа 2026

Два прохода Косарайю выделяют SCC и сразу нумеруют конденсацию в топологическом порядке — без её явного построения.

Результат

Статус

Accepted. Использован алгоритм Косарайю: postorder исходного графа и DFS по транспонированному графу в обратном порядке выхода.

  • время: \(\Theta(n+m)\);
  • память: \(\Theta(n+m)\);
  • номера компонент уже задают топологический порядок конденсации.

Условие

Разбиение ориентированного графа

Дан ориентированный мультиграф \(G=(V,E)\), где \(V=\{1,2,\ldots,n\}\), \(1\le n,m\le5\cdot10^5\). Разрешены петли и кратные рёбра.

Нужно назначить каждой вершине номер её компоненты сильной связности так, чтобы для каждого ребра \((u,v)\in E\)

\[ \boxed{ comp[u]=comp[v] \quad\text{или}\quad comp[u]<comp[v] }. \]

Определения

Сильная связность и конденсация

Вершины \(u\) и \(v\) сильно связны, если взаимно достижимы:

\[ u\sim v \iff u\rightsquigarrow v \ \land\ v\rightsquigarrow u. \]

Это отношение эквивалентности, а его классы называются SCC. Если сжать каждую SCC в одну вершину, получится конденсация \(G^{\mathrm{SCC}}\).

Свойство

Почему конденсация ациклична

Если бы различные компоненты образовали цикл

\[ C_1\to C_2\to\cdots\to C_k\to C_1, \]

из любой из них можно было бы попасть в любую другую и вернуться обратно. Тогда все вершины цикла принадлежали бы одной SCC, что противоречит их различию. Поэтому

\[ \boxed{G^{\mathrm{SCC}}\text{ является DAG}}. \]

Ключевая идея

Два прохода Косарайю

  1. Выполнить DFS в исходном графе и добавлять вершины в order при выходе.
  2. Просматривать вершины в обратном порядке выхода.
  3. Из каждой ещё не размеченной вершины запускать DFS в транспонированном графе.
  4. Все вершины одного запуска второго DFS получают общий номер.

Для SCC \(C\) обозначим максимальное время выхода её вершины через \(F(C)\). Для ребра конденсации

\[ C\to D, \qquad C\ne D, \]

выполняется

\[ \boxed{F(C)>F(D)}. \]

Значит, reverse postorder перечисляет компоненты от источников конденсации к стокам.

Транспонирование

Зачем обращать рёбра

В транспонированном графе

\[ (u,v)\in E(G) \iff (v,u)\in E(G^T). \]

SCC не меняются: взаимные пути просто обращаются. Межкомпонентные рёбра меняют направление. Компонента, выбранная первой среди ещё не обработанных, является источником исходной конденсации; в транспонированной конденсации из неё нельзя выйти в другую ещё не размеченную SCC. Поэтому один второй DFS выделяет ровно одну компоненту.

Реализация идеи

Первый и второй проходы

Postorder исходного графа

Первый DFS использует color как обычный visited и добавляет вершину только после всех исходящих рёбер. Внешний цикл посещает все компоненты, поэтому \(|\texttt{order}|=n\).

Разметка обратного графа

comp[v] == 0 означает, что вершина ещё не назначена компоненте. Перед новым запуском счётчик увеличивается, а все достижимые по обратным рёбрам неразмеченные вершины получают этот номер.

Доказательство

Корректность и порядок номеров

Первой во втором проходе выбирается вершина SCC с максимальным \(F(C)\) среди неразмеченных компонент. Это источник оставшейся исходной конденсации и сток её транспонирования, поэтому второй DFS не покидает компоненту. Внутри SCC все вершины остаются взаимно достижимыми и будут посещены.

После удаления этой компоненты рассуждение повторяется. Компоненты получают номера в порядке источников исходной конденсации, следовательно для любого межкомпонентного ребра \(C\to D\)

\[ \boxed{comp(C)<comp(D)}. \]

Минимальная проверка

Почему порядок критичен

В графе \(1\to2\) вершины образуют разные SCC. В обратном графе есть ребро \(2\to1\). Если начать второй проход с вершины \(2\), компоненты ошибочно сольются. Reverse postorder заставляет сначала обработать \(1\).

Реализация

Accepted-код

#include <iostream>
#include <vector>

int main() {
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);

  int n;
  int m;
  std::cin >> n >> m;

  std::vector<std::vector<int>> adj(n + 1);
  std::vector<std::vector<int>> adj_reverse(n + 1);
  for (int i = 0; i < m; ++i) {
    int u;
    int v;
    std::cin >> u >> v;
    adj[u].push_back(v);
    adj_reverse[v].push_back(u);
  }

  std::vector<int> color(n + 1, 0);
  std::vector<int> order;
  order.reserve(n);

  auto dfs1 = [&](auto&& self, int v) -> void {
    color[v] = 1;
    for (int u : adj[v]) {
      if (color[u] == 0) {
        self(self, u);
      }
    }
    order.push_back(v);
  };

  for (int v = 1; v <= n; ++v) {
    if (color[v] == 0) {
      dfs1(dfs1, v);
    }
  }

  std::vector<int> comp(n + 1, 0);
  int comp_cnt = 0;
  auto dfs2 = [&](auto&& self, int v) -> void {
    comp[v] = comp_cnt;
    for (int u : adj_reverse[v]) {
      if (comp[u] == 0) {
        self(self, u);
      }
    }
  };

  for (int i = n - 1; i >= 0; --i) {
    int v = order[i];
    if (comp[v] == 0) {
      ++comp_cnt;
      dfs2(dfs2, v);
    }
  }

  std::cout << comp_cnt << '\n';
  for (int v = 1; v <= n; ++v) {
    std::cout << comp[v] << ' ';
  }
}

Оценка

Сложность

Оба DFS посещают каждую вершину один раз и просматривают каждое ребро постоянное число раз:

\[ \boxed{T(n,m)=\Theta(n+m)}. \]

Исходный и обратный графы, служебные массивы, порядок и рекурсивные стеки занимают

\[ \boxed{W(n,m)=\Theta(n+m)}. \]

Разбор кода

Технические детали

  • order.reserve(n) выделяет память, но не меняет размер вектора;
  • color не сбрасывается: второй проход использует comp как посещённость и ответ;
  • цикл от \(n-1\) корректен, потому что первый проход добавляет в order все \(n\) вершин;
  • номер увеличивается до dfs2, поскольку ноль зарезервирован для неразмеченных вершин;
  • петли и кратные рёбра не меняют SCC и не влияют на асимптотику.

Проверки

Граничные случаи

  • сильно связный граф получает один номер;
  • DAG разбивается на одноэлементные SCC, а номера образуют топологический порядок;
  • петля остаётся внутри компоненты своей вершины;
  • несвязанные части обрабатываются обоими внешними циклами;
  • кратные рёбра предъявляют то же условие порядка.

Разбор ошибок

Типичные неверные подходы

  1. Искать обычные компоненты связности. Для SCC нужна взаимная, а не односторонняя достижимость.
  2. Считать DFS-деревья SCC. Один DFS может пройти через несколько компонент по рёбрам конденсации.
  3. Запускать второй проход в произвольном порядке. Это может склеить разные SCC.
  4. Во втором проходе использовать исходный граф. DFS из источника сможет уйти по конденсации.
  5. Просматривать order прямо. Нужен порядок убывания времени выхода.
  6. Использовать ноль как номер первой SCC. Тогда он перестаёт обозначать непосещённую вершину.
  7. Забыть внешние циклы. Часть графа останется необработанной.
  8. Строить и сортировать конденсацию без необходимости. Порядок второго прохода уже даёт нужную нумерацию.

Надёжность

Глубина рекурсии

В худшем случае глубина каждого DFS равна \(\Theta(n)\). При \(n=5\cdot10^5\) это чувствительно к размеру системного стека. Принятое решение прошло тесты контеста, но переносимый вариант может использовать явные стеки для обоих проходов.

Сравнение

Косарайю и Тарьян

Оба алгоритма работают за \(\Theta(n+m)\). Косарайю выполняет два обхода и хранит транспонированный граф; Тарьян использует один проход, времена входа, low и стек активных вершин. Здесь Косарайю удобен тем, что порядок второго прохода сразу даёт требуемые номера компонент.

Перенос идеи

Как распознать паттерн

  • дан ориентированный граф;
  • важна взаимная достижимость;
  • вершины нужно объединить в максимальные группы;
  • после объединения анализируются зависимости между группами;
  • ограничения требуют линейного алгоритма.
\[ \text{SCC} \ +\ \text{исходный и обратный графы} \Longrightarrow \text{два DFS по reverse postorder}. \]

Вывод

Главный итог

Первый проход выбирает источник среди ещё не обработанных компонент. После транспонирования из него нельзя выйти в другую неразмеченную SCC, поэтому второй DFS выделяет ровно одну компоненту. Порядок последовательного удаления источников автоматически обеспечивает

\[ \boxed{ (u,v)\in E \implies comp[u]=comp[v] \ \text{или}\ comp[u]<comp[v] }. \]
