Семестр 2 · Контест 3

Задача B — Компоненты связности неориентированного графа

Accepted · C++ · 31 июля 2026

Каждый запуск DFS из ещё не посещённой вершины находит ровно одну полную компоненту связности, поэтому весь граф разбирается за линейное время.

Результат

Статус

Accepted. Граф хранится списками смежности, а DFS запускается из каждой ещё не посещённой вершины.

  • ожидаемое время принятой реализации: \(\Theta(n+m)\);
  • память: \(\Theta(n+m)\);
  • порядок компонент и вершин может быть произвольным.

Условие

Разбиение на компоненты

Дан неориентированный граф

\[ G=(V,E), \qquad V=\{1,2,\ldots,n\}, \qquad |E|=m, \]

где \(1\le n\le2\cdot10^5\) и \(0\le m\le2\cdot10^5\). Нужно вывести число компонент связности, размер каждой компоненты и входящие в неё вершины.

Определение

Почему компоненты образуют разбиение

Вершины \(u\) и \(v\) связаны, если между ними существует путь. В неориентированном графе отношение

\[ u\sim v \quad\Longleftrightarrow\quad \text{существует путь из }u\text{ в }v \]

рефлексивно, симметрично и транзитивно. Его классы эквивалентности — максимальные множества взаимно достижимых вершин, то есть компоненты связности.

Наблюдение

Один DFS — одна компонента

DFS из ещё не посещённой вершины \(s\) посещает в точности её компоненту:

  • обход переходит только по рёбрам и не может покинуть компоненту;
  • до любой вершины компоненты существует путь из \(s\), по которому DFS рано или поздно пройдёт.

После завершения обхода вся компонента помечена, поэтому новый DFS нужен только для белой вершины.

Количество компонент равно числу корней DFS-леса.

Представление

Хранимая информация

Списки смежности

Каждое неориентированное ребро добавляется в обе стороны:

adj[u].push_back(v);
adj[v].push_back(u);

Цвета вершин

  • 0 — вершина ещё не посещена;
  • 1 — DFS вошёл в вершину;
  • 2 — все её соседи рассмотрены.

Для компонент достаточно булева visited; три цвета в принятом коде являются универсальной, но избыточной схемой.

Компоненты

Принятая реализация хранит каждую компоненту в std::unordered_set<int>. Множество автоматически устраняет повторную вставку, а произвольный порядок разрешён условием.

Инварианты

Корректность обхода

Один вызов DFS

  • каждая добавленная вершина связана с корнем текущего обхода;
  • каждая вершина вводится в DFS не более одного раза;
  • переход в белого соседа остаётся внутри той же компоненты;
  • при завершении вершины рассмотрены все её рёбра.

Внешний цикл

Перед очередной вершиной уже созданные множества совпадают с полными попарно непересекающимися компонентами. Их вершины посещены, а остальные остаются белыми. Поэтому белая вершина принадлежит ровно одной ещё не найденной компоненте.

Алгоритм

DFS и внешний цикл

  1. Построить двусторонние списки смежности.
  2. В dfs(v, i) пометить \(v\), добавить её в компоненту \(i\) и рекурсивно обработать всех белых соседей.
  3. Перебрать вершины от \(1\) до \(n\).
  4. Для каждой белой вершины создать новую компоненту и запустить DFS.
  5. Вывести найденные множества.

Доказательство

Почему ответ точен

DFS не добавляет вершины из другой компоненты, потому что каждый переход идёт по ребру. С другой стороны, он не пропускает вершину своей компоненты: вдоль любого пути от корня первая ещё не посещённая вершина будет обнаружена при просмотре ребра из уже достигнутой.

Следовательно, один запуск создаёт ровно одну полную компоненту. Глобальная отметка не позволяет создать её повторно, а внешний цикл запускает обход для каждой оставшейся белой вершины, включая изолированные. Поэтому все вершины входят ровно в одну выведенную компоненту.

Реализация

Accepted-код

#include <functional>
#include <iostream>
#include <unordered_set>
#include <vector>

int main() {
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);

  int n;
  int m;
  std::cin >> n >> m;

  std::vector<std::vector<int>> adj(n + 1);
  for (int i = 0; i < m; ++i) {
    int u;
    int v;
    std::cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);
  }

  std::vector<int> color(n + 1, 0);
  std::vector<std::unordered_set<int>> component;
  component.reserve(n + 1);

  std::function<void(int, int)> dfs = [&](int v, int i) {
    color[v] = 1;
    component[i].insert(v);

    for (int u : adj[v]) {
      if (color[u] == 0) {
        component[i].insert(u);
        dfs(u, i);
      }
    }

    color[v] = 2;
  };

  for (int v = 1; v <= n; ++v) {
    if (color[v] == 0) {
      component.push_back(std::unordered_set<int>());
      dfs(v, component.size() - 1);
    }
  }

  std::cout << component.size() << '\n';
  for (const auto& comp : component) {
    std::cout << comp.size() << '\n';
    for (const auto& v : comp) {
      std::cout << v << ' ';
    }
    std::cout << '\n';
  }
}

Оценка

Сложность

Каждая вершина впервые посещается один раз. Каждое неориентированное ребро просматривается дважды — по одному разу с каждого конца. Вывод всех вершин также занимает линейное время.

Для принятой реализации с unordered_set оценка ожидаемая:

\[ \boxed{T(n,m)=\Theta(n+m)}. \]

Списки смежности, отметки, компоненты и рекурсивный стек занимают

\[ \boxed{W(n,m)=\Theta(n+m)}. \]

При хранении компонент в обычных векторах линейная временная оценка становится гарантированной.

Проверки

Граничные случаи

  • граф без рёбер состоит из \(n\) одноэлементных компонент;
  • связный граф создаёт одну компоненту;
  • изолированная вершина обрабатывается внешним циклом;
  • петли и кратные рёбра не создают повторных вершин в компоненте;
  • порядок обхода unordered_set не фиксирован, но условие допускает любой порядок.

Разбор ошибок

Типичные ошибки

  1. Добавить ребро только в одну сторону. Тогда обход работает с ориентированным графом и может разбить одну компоненту на несколько частей.
  2. Запустить DFS только из вершины 1. Остальные компоненты останутся необработанными.
  3. Пометить вершину после рекурсивных переходов. Соседние вершины начнут бесконечно вызывать друг друга.
  4. Создавать компоненту для каждой вершины. Новая запись нужна только для белой вершины.
  5. Забыть изолированные вершины. Каждая из них образует компоненту размера один.
  6. Заменить множество на vector, сохранив две вставки. В принятом коде сосед вставляется до рекурсии и повторно внутри неё; вектор сохранил бы дубликаты.
  7. Полагаться на порядок unordered_set. Стандарт его не гарантирует.
  8. Не учитывать вывод. Перечисление всех вершин само требует \(\Omega(n)\).

Улучшения

Как упростить реализацию

  • убрать вставку соседа перед рекурсией: dfs(u, i) сам добавит вершину;
  • заменить unordered_set на vector и вставлять каждую вершину один раз;
  • заменить три цвета на булев visited;
  • при чувствительном размере стека использовать итеративный DFS.

Глубина рекурсии в худшем случае равна \(\Theta(n)\). При \(n=2\cdot10^5\) явный стек делает решение переносимее.

component.reserve(n + 1) резервирует место только во внешнем векторе и не создаёт компоненты заранее.

Перенос идеи

Как распознать паттерн

  • дан неориентированный граф;
  • нужно разбить вершины на группы взаимной достижимости;
  • требуются число компонент, их размеры или вершины;
  • граф может быть несвязным и содержать изолированные вершины;
  • ограничения требуют линейного обхода.
\[ \text{белая вершина} \Longrightarrow \text{новый корень DFS} \Longrightarrow \text{одна полная компонента}. \]

Вывод

Главный итог

Компоненты не нужно строить попарными проверками. Один обход из вершины находит в точности её класс достижимости, а глобальная отметка не позволяет обрабатывать его повторно:

\[ \boxed{ \text{каждый новый корень DFS соответствует ровно одной компоненте} }. \]
