Семестр 1 · Контест 3

Задача B — Марафон

Accepted · C++ · 2 августа 2026

Монотонное продвижение бегуна превращается в прибавление на диапазоне порогов, а его ранг — в один точечный запрос.

Результат

Статус

Accepted. Использован Segment Tree с lazy propagation для операций range add и point query.

  • один запрос: \(O(\log D)\);
  • все запросы: \(O(D+q\log D)\);
  • память: \(O(D+R)\).

Условие

Онлайн-запросы о бегунах

Дистанция содержит точки \(1,2,\ldots,D\), где \(D=42195\), а спортсменов не более \(R=10^5\).

  • RUN i p — спортсмен \(i\) достиг позиции \(p\); его позиции строго возрастают;
  • CHEER i — доля остальных активных спортсменов, пробежавших строго меньше.

До первого RUN ответ равен 0. Если активен только запрошенный спортсмен, ответ равен 1.

Медленный подход

Почему нельзя перебирать спортсменов

Хранить текущую позицию легко, но каждый CHEER потребовал бы просмотра всех активных участников. В худшем случае это \(O(qR)\), то есть до \(10^{10}\) операций.

Ключевое наблюдение

Счётчики выполненных порогов

Для каждой точки определим

\[ C[x]=\#\{j:\operatorname{pos}_j\ge x\}. \]

Если бегун переместился из old в new, он уже учтён в \(C[1],\ldots,C[old]\) и должен дополнительно попасть ровно в

\[ C[old+1],C[old+2],\ldots,C[new]. \]

Поэтому RUN — это прибавление единицы на \([old+1,new]\). Последовательные диапазоны одного бегуна не пересекаются и вместе образуют \([1,p]\).

Формула

Ответ на CHEER

Пусть активны \(A\) спортсменов, а позиция запрошенного бегуна равна \(p>0\). Значение \(C[p]\) считает самого бегуна, участников на той же позиции и всех впереди. Поэтому строго более медленных:

\[ slower=A-C[p]. \]

Всего остальных активных участников \(A-1\), значит при \(A>1\)

\[ \boxed{answer=\frac{A-C[p]}{A-1}}. \]

Равная позиция не считается меньшей; дополнительно вычитать самого бегуна из числителя не нужно.

Lazy propagation

Что хранит дерево

Дерево построено над координатами от \(0\) до \(D\). Для узла на \([l,r]\) значение tree[v] равно сумме \(C[x]\) на отрезке, а lazy[v] — отложенной прибавке ко всем его точкам.

tree_[v] += static_cast<long long>(right - left + 1) * value;
lazy_[v] += value;

Push передаёт прибавку сыновьям, Pull восстанавливает сумму родителя, а GetPoint(p) выполняется как запрос суммы на \([p,p]\).

Состояние

Инварианты алгоритма

  1. runs[i] — последняя позиция бегуна или ноль до первого RUN.
  2. active_runners — число бегунов с положительной позицией.
  3. Каждый лист \(x\ge1\) хранит \(C[x]=\#\{j:\texttt{runs[j]}\ge x\}\).
  4. Внутренний узел хранит сумму своих листьев с учётом отложенного обновления.

Доказательство

Корректность обновлений и ответа

При первом RUN счётчик активных увеличивается ровно один раз. При переходе \(old\to new\) предикат \(pos_i\ge x\) меняется с ложного на истинный только для \(old<x\le new\), поэтому обновление диапазона сохраняет точный смысл всех \(C[x]\).

Операции Apply, Push и Pull сохраняют суммы узлов, следовательно, точечный запрос возвращает точное \(C[p]\). После обработки особых случаев формула \((A-C[p])/(A-1)\) даёт требуемую долю.

Важное исправление

Почему tree_ требует long long

Лист не превосходит \(10^5\), но корень хранит сумму всех пороговых счётчиков:

\[ \sum_{x=1}^{D}C[x]=\sum_i pos_i. \]

Если все \(10^5\) бегунов на финише, сумма равна \(42195\cdot10^5=4\,219\,500\,000>\texttt{INT\_MAX}\). Принятый вариант с int прошёл тесты, но строгая реализация должна хранить tree_ в long long; ниже тип исправлен.

Реализация

Код с усиленным типом

#include <iostream>
#include <string>
#include <vector>

constexpr int cDistance = 42'195;
constexpr int cRunners = 100'000;
constexpr int cPrecision = 8;

class SegmentTree {
 public:
  explicit SegmentTree(int n) {
    while (N_ < n) N_ *= 2;
    tree_.assign(N_ * 2, 0);
    lazy_.assign(N_ * 2, 0);
  }

  void AddRange(int left, int right) {
    AddRange(1, 0, N_ - 1, left, right, 1LL);
  }
  long long GetPoint(int position) {
    return RangeSum(1, 0, N_ - 1, position, position);
  }

 private:
  long long RangeSum(int v, int left, int right, int ql, int qr) {
    if (qr < left || right < ql) return 0;
    if (ql <= left && right <= qr) return tree_[v];
    Push(v, left, right);
    int middle = left + (right - left) / 2;
    return RangeSum(v * 2, left, middle, ql, qr) +
           RangeSum(v * 2 + 1, middle + 1, right, ql, qr);
  }

  void AddRange(int v, int left, int right, int ql, int qr,
                long long value) {
    if (qr < left || right < ql) return;
    if (ql <= left && right <= qr) {
      Apply(v, left, right, value);
      return;
    }
    Push(v, left, right);
    int middle = left + (right - left) / 2;
    AddRange(v * 2, left, middle, ql, qr, value);
    AddRange(v * 2 + 1, middle + 1, right, ql, qr, value);
    tree_[v] = tree_[v * 2] + tree_[v * 2 + 1];
  }

  void Apply(int v, int left, int right, long long value) {
    tree_[v] += static_cast<long long>(right - left + 1) * value;
    lazy_[v] += value;
  }
  void Push(int v, int left, int right) {
    if (lazy_[v] == 0 || left == right) return;
    int middle = left + (right - left) / 2;
    Apply(v * 2, left, middle, lazy_[v]);
    Apply(v * 2 + 1, middle + 1, right, lazy_[v]);
    lazy_[v] = 0;
  }

  int N_{1};
  std::vector<long long> tree_;
  std::vector<long long> lazy_;
};

int main() {
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);
  std::cout.precision(cPrecision);
  int query_count;
  std::cin >> query_count;
  SegmentTree segment_tree(cDistance + 1);
  std::vector<int> runs(cRunners, 0);
  int active_runners = 0;

  while (query_count-- > 0) {
    std::string command;
    std::cin >> command;
    if (command == "RUN") {
      int runner, new_position;
      std::cin >> runner >> new_position;
      --runner;
      int old_position = runs[runner];
      if (old_position == 0) ++active_runners;
      segment_tree.AddRange(old_position + 1, new_position);
      runs[runner] = new_position;
    } else {
      int runner;
      std::cin >> runner;
      --runner;
      int position = runs[runner];
      if (position == 0) {
        std::cout << 0 << '\n';
      } else if (active_runners == 1) {
        std::cout << 1 << '\n';
      } else {
        long long not_slower = segment_tree.GetPoint(position);
        long long slower = active_runners - not_slower;
        std::cout << static_cast<double>(slower) /
                         static_cast<double>(active_runners - 1) << '\n';
      }
    }
  }
}

Самопроверка

Граничные случаи

  • до первого RUN дерево не запрашивается и выводится 0;
  • при одном активном бегуне выводится 1 без деления на ноль;
  • равные позиции не входят в число строго более медленных;
  • первый RUN обновляет \([1,new]\) и увеличивает число активных;
  • последующие RUN обновляют только \([old+1,new]\);
  • правый конец \(42195\) входит в дерево.

Обобщение

Как распознать паттерн

Полезно перейти к порогам, когда запросы идут онлайн, значение объекта меняется монотонно, а ответ связан с рангом. Переход \(old\to new\) меняет предикат value >= x на непрерывном диапазоне \((old,new]\).

Храним число объектов, выполнивших каждый порог. Монотонное изменение становится обновлением диапазона, а ранговый запрос — чтением одного порогового счётчика.
