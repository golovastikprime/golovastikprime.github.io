Семестр 1 · Контест 4

Задача H — Площадь объединения прямоугольников

Accepted · C++ · 20 июля 2026

Следовательно, задача сводится к последовательной обработке событий и поддержанию длины объединения активных отрезков на оси y.

Условие

Задача

Даны n прямоугольников со сторонами, параллельными координатным осям. Требуется найти площадь их объединения.

Вырожденные прямоугольники, у которых x1 = x2 или y1 = y2, имеют нулевую площадь и могут быть пропущены.

Для алгоритма прямоугольник удобно представлять полуоткрытым множеством

[x1, x2) × [y1, y2).

Выбор открытых или закрытых границ не меняет площадь.

Подход

Ключевое наблюдение

Вертикальные границы прямоугольников разбивают плоскость на полосы между соседними координатами событий.

Для каждого невырожденного прямоугольника создаются два события:

  • в x1 его y-отрезок [y1, y2) добавляется;
  • в x2 этот отрезок удаляется.

Между соседними координатами событий множество активных прямоугольников не меняется. Поэтому объединение их проекций на ось y также постоянно на всей полосе.

Если предыдущая координата события равна xprev, текущая — x, а длина объединения активных y-отрезков равна L, то площадь этой полосы равна

(x − xprev) · L.

Следовательно, задача сводится к последовательной обработке событий и поддержанию длины объединения активных отрезков на оси y.

Sweep line

Представление и обработка событий

Для прямоугольника

[x1, x2) × [y1, y2)

создаются события

(x1, y1, y2, +1),  (x2, y1, y2, −1).

События сортируются по x и обрабатываются группами с одинаковой координатой. Перед применением группы с координатой x добавляется площадь предыдущей полосы:

answer += (x − xprev) · length[root].

Затем применяются все добавления и удаления из этой группы, после чего полагается

xprev = x.

События с одинаковым x не создают полосы положительной ширины, поэтому порядок событий внутри одной группы не влияет на итоговую площадь.

Если после пропуска вырожденных прямоугольников событий нет, ответ сразу равен нулю и дерево строить не требуется.

Координаты

Сжатие координат

Собираются все границы y1 и y2 невырожденных прямоугольников. После сортировки и удаления повторений получается массив

y0 < y1 < … < ym−1.

Лист с индексом i представляет не отдельную координату, а элементарный промежуток

[yi, yi+1).

Поэтому существует m−1 элементарных промежутков, а корень дерева отвечает за полуинтервал индексов

[0, m−1),

то есть за геометрический интервал

[y0, ym−1).

Исходный отрезок [yl, yr) после сжатия становится запросом

[pos(yl), pos(yr)).

Структура данных

Информация в дереве отрезков

Для вершины v, отвечающей за геометрический интервал Iv, хранятся:

  • count[v] — число активных обновлений, которые полностью покрыли Iv и завершили рекурсию именно в вершине v;
  • length[v] — длина покрытия внутри Iv, представленная счётчиками в поддереве вершины v.

Важно: покрытие, записанное в предке вершины, геометрически покрывает Iv, но не входит в count[v] и length[v]. Для получения глобальной длины используется корень, у которого нет предков.

Инвариант вершины

Пересчёт вершины

Пусть вершина отвечает за индексы [l, r), то есть за геометрический интервал

[yl, yr).

Тогда

length[v] =
⎧ yr − yl, если count[v] > 0;
⎪ 0, если count[v] = 0 и r − l = 1;
⎩ length[left(v)] + length[right(v)], если count[v] = 0 и v не лист.

Если count[v] > 0, весь интервал вершины покрыт независимо от состояния потомков.

Если count[v] == 0, покрытие, представленное внутри поддерева вершины, определяется сохранёнными состояниями детей.

Обычный Push здесь не требуется: count[v] не является отложенным обновлением, которое должно быть передано детям.

Операция дерева

Обновление отрезка

Для запроса [ql, qr) с изменением delta:

  1. Если интервалы не пересекаются, ничего не делаем.
  2. Если интервал вершины полностью содержится в запросе:
    • выполняем count[v] += delta;
    • пересчитываем length[v];
    • завершаем рекурсию.
  3. При частичном пересечении:
    • обновляем пересекающихся детей;
    • пересчитываем текущую вершину.

Даже если count[v] > 0, при частичном запросе необходимо обновлять потомков. Их значения временно не влияют на length[v], но понадобятся, когда полное покрытие вершины будет удалено.

Добавление и последующее удаление одного и того же сжатого отрезка проходят по одной и той же канонической декомпозиции дерева. Поэтому удаление уменьшает именно те счётчики, которые были увеличены при добавлении.

Корректность sweep line

Инвариант sweep line

Перед обработкой группы событий с координатой x дерево описывает объединение y-проекций прямоугольников, активных на полосе

[xprev, x).

Между xprev и x нет вертикальных границ прямоугольников. Поэтому множество активных прямоугольников и длина объединения их y-проекций постоянны на всей полосе.

Следовательно,

(x − xprev) · length[root]

равно площади объединения прямоугольников внутри этой полосы.

После добавления площади применяются все события с координатой x, и дерево начинает описывать следующую полосу. Сумма вкладов всех полос равна площади всего объединения.

Корректность дерева

Доказательство корректности дерева

Для вершины v обозначим через Uv объединение геометрических интервалов всех вершин u в поддереве v, для которых

count[u] > 0.

Докажем по индукции по высоте вершины, что

length[v] = |Uv|.

База

Пусть v — лист, соответствующий элементарному промежутку

[yi, yi+1).

Если count[v] > 0, то Uv совпадает со всем промежутком, поэтому

length[v] = yi+1 − yi = |Uv|.

Если count[v] == 0, в поддереве листа нет других вершин, поэтому Uv = ∅ и length[v] = 0.

Индукционный переход

Пусть утверждение верно для детей внутренней вершины v.

Если count[v] > 0, то интервал Iv сам входит в объединение Uv. Все интервалы из поддерева содержатся в Iv, поэтому

Uv = Iv

и

length[v] = |Iv| = |Uv|.

Если count[v] == 0, то

Uv = Uleft(v) ∪ Uright(v).

Интервалы детей не пересекаются и вместе образуют Iv. Поэтому по индукционному предположению

|Uv| = |Uleft(v)| + |Uright(v)|
= length[left(v)] + length[right(v)]
= length[v].

Значит, утверждение верно для любой вершины.

Каждый активный y-отрезок раскладывается обновлением на объединение интервалов канонических вершин дерева. Поэтому Uroot совпадает с объединением всех активных y-отрезков, а length[root] равна его длине.

Совместно с инвариантом sweep line это доказывает корректность всего алгоритма.

Оценка ресурсов

Сложность

Создаётся не более 2n событий и собирается не более 2n координат y.

  • сортировка событий: O(n log n);
  • сортировка координат: O(n log n);
  • поиск сжатых границ каждого события: O(log n);
  • одно обновление дерева: O(log n);
  • число событий: O(n).

Итоговая временная сложность:

T(n) = O(n log n).

Массив событий, координаты и дерево отрезков занимают линейную память:

M(n) = O(n).

Глубина рекурсии дерева равна O(log n).

Разности координат, покрытую длину, произведение ширины полосы на её высоту и итоговый ответ следует вычислять в достаточно широком целочисленном типе; при стандартных ограничениях с координатами типа int для этого используется long long.

История поиска

Главная ошибка

Первая версия дерева пыталась использовать стандартную схему range add + range sum с lazy propagation.

Это неверно, потому что требуется хранить не сумму кратностей покрытия, а длину множества точек, покрытых хотя бы один раз.

Например, если два одинаковых прямоугольника полностью совпадают, длина их объединения не удваивается.

Правильная структура хранит отдельно:

  • число полных покрытий вершины count[v];
  • фактическую длину объединения length[v].

При этом count[v] не нужно проталкивать детям: частичные покрытия независимо сохраняются ниже по дереву.

Перенос идеи

Признаки похожих задач

Sweep line применим, когда:

  • состояние меняется только в конечном наборе координат-событий;
  • между соседними событиями состояние остаётся постоянным;
  • каждое событие локально добавляет или удаляет объект;
  • вклад между событиями можно вычислить из некоторого агрегата текущего состояния.

В этой задаче событие добавляет или удаляет отрезок по второй координате, а требуемый агрегат — длина объединения активных отрезков.

Дополнительные признаки для coordinate compression:

  • координаты могут быть большими;
  • заранее известны все координаты, в которых состояние может измениться;
  • важны порядок и расстояния между соседними координатами, а не все точки числовой оси;
  • листья должны представлять промежутки между соседними координатами, поскольку требуется геометрическая длина.
