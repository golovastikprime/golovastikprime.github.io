Семестр 1 · Контест 4

Задача G — сумма элементов мультимножества, не превосходящих x

Accepted · C++

Запрос ? x сводится к вычислению суммы на префиксе сжатых координат.

Условие

Задача

Изначально дано пустое мультимножество \(S\). Требуется обработать запросы двух типов:

  • + x — добавить число \(x\) в \(S\);
  • ? x — вывести сумму всех элементов \(S\), не превосходящих \(x\).

Ограничения:

  • \(1 \le q \le 10^5\);
  • \(0 \le x \le 10^9\).

Подход

Ключевое наблюдение

Все запросы известны заранее. Поэтому можно собрать все различные значения из операций +, отсортировать их и закрепить за каждым значением постоянный индекс.

После этого при + x не требуется физически вставлять элемент в середину отсортированного массива и сдвигать остальные элементы. Вместо этого обновляется уже существующая позиция pos(x) в структуре данных.

Поскольку массив координат отсортирован, условие

\[v \le x\]

соответствует префиксу

\[\bigl[0, k\bigr), \qquad k = \operatorname{upper\_bound}(\mathrm{coords}, x).\]

Следовательно, запрос ? x сводится к вычислению суммы на префиксе сжатых координат.

Структура данных

Хранимая информация

Пусть coords[i] — \(i\)-я различная координата, а count[i] — количество уже обработанных операций + coords[i].

Лист дерева, соответствующий координате coords[i], хранит

\[\mathrm{tree}[N+i] = \mathrm{coords}[i] \cdot \mathrm{count}[i].\]

Внутренняя вершина \(v\), отвечающая за диапазон индексов координат \(\bigl[l, r\bigr)\), хранит

\[\mathrm{tree}[v] = \sum_{i=l}^{r-1} \mathrm{coords}[i] \cdot \mathrm{count}[i].\]

То есть каждая вершина хранит сумму всех уже добавленных элементов, координаты которых лежат в её диапазоне.

Алгоритм

Обработка запросов

Вставка + x

  1. Найти сжатый индекс \(i = \operatorname{pos}(x)\).
  2. Увеличить count[i] на единицу.
  3. Обновить лист:
\[\mathrm{tree}[N+i] = \mathrm{coords}[i] \cdot \mathrm{count}[i].\]
  1. Пересчитать вершины на пути от листа к корню как сумму двух детей.

Эквивалентно можно не хранить count[i] отдельно, а при каждой вставке прибавлять \(x\) к соответствующему листу.

Запрос ? x

Найти

\[k = \operatorname{upper\_bound}(\mathrm{coords}, x).\]

По определению upper_bound:

\[ \begin{cases} \mathrm{coords}[i] \le x, & \forall i \lt k, \\ \mathrm{coords}[i] > x, & \forall i \ge k. \end{cases} \]

Поэтому все и только подходящие координаты находятся в префиксе \(\bigl[0, k\bigr)\). Ответ равен сумме дерева на этом префиксе.

Почему это работает

Доказательство корректности

Инвариант дерева

После обработки любого префикса запросов для каждой вершины \(v\), отвечающей за диапазон \(\bigl[l, r\bigr)\), выполняется

\[\mathrm{tree}[v] = \sum_{i=l}^{r-1} \mathrm{coords}[i] \cdot \mathrm{count}[i].\]

База

До обработки запросов мультимножество пусто, поэтому для всех \(i\)

\[\mathrm{count}[i] = 0.\]

Следовательно, все листья и все внутренние вершины дерева равны нулю, и инвариант выполнен.

Сохранение при + x

Пусть \(i = \operatorname{pos}(x)\). После вставки изменяется только count[i], поэтому меняется только вклад листа \(N+i\).

Вершины, диапазоны которых не содержат \(i\), не зависят от этого листа и остаются корректными.

Вершины, диапазоны которых содержат \(i\), образуют путь от листа к корню. При пересчёте каждой такой вершины как суммы её детей значение снова становится суммой вкладов всех листьев её диапазона. Значит, инвариант сохраняется.

Корректность ? x

Пусть

\[k = \operatorname{upper\_bound}(\mathrm{coords}, x).\]

Тогда индексы \(0, \ldots, k-1\) соответствуют всем и только значениям, не превосходящим \(x\). По инварианту дерева сумма на \(\bigl[0, k\bigr)\) равна

\[\sum_{i=0}^{k-1} \mathrm{coords}[i] \cdot \mathrm{count}[i],\]

то есть сумме всех уже добавленных элементов мультимножества \(S\), не превосходящих \(x\), с учётом кратности.

Оценка ресурсов

Сложность

Пусть \(m \le q\) — число различных значений в операциях +.

  • чтение запросов и сбор координат: \(\mathcal{O}(q)\);
  • сортировка координат: \(\mathcal{O}(q \log q)\);
  • удаление дубликатов: \(\mathcal{O}(q)\);
  • построение дерева: \(\mathcal{O}(m)\);
  • каждая вставка: \(\mathcal{O}(\log m)\);
  • каждый запрос суммы: \(\mathcal{O}(\log m)\).

Итого:

\[T(q) = \mathcal{O}(q \log q), \qquad M(q) = \mathcal{O}(q).\]

Для сумм необходим long long, поскольку максимальный ответ может достигать

\[10^5 \cdot 10^9 = 10^{14}.\]

История поиска

Главный тупик

Первоначальная идея состояла в поддержании реального отсортированного мультимножества в vector и явных prefix sums.

Это приводит к двум линейным операциям:

  • вставка в середину vector требует сдвига \(\mathcal{O}(q)\) элементов;
  • после вставки требуется изменить \(\mathcal{O}(q)\) последующих префиксных сумм.

Поэтому одна вставка могла стоить \(\mathcal{O}(q)\), а вся последовательность запросов — \(\mathcal{O}(q^2)\) в худшем случае.

Корневая ошибка состояла в попытке поддерживать динамический порядок элементов физически, хотя все возможные координаты были известны заранее и могли получить постоянные индексы.

Перенос идеи

Признаки похожих задач

Подход offline coordinate compression + point update + prefix query стоит проверять, когда:

  • все возможные координаты обновлений известны заранее;
  • обновление изменяет одну координату;
  • запрос задаётся неравенством вида \(v \le x\) или \(v \lt x\);
  • после сортировки условие превращается в префикс;
  • по префиксу требуется вычислять агрегат: сумму, количество, максимум и т. п.;
  • физическая вставка в отсортированный массив была бы слишком дорогой.

Для суммы и количества префиксов часто достаточно Fenwick tree; дерево отрезков полезно, если в дальнейшем нужны более общие запросы по диапазонам.

Post-Accepted

Содержательные уточнения к первоначальному пересказу

  1. Исправлено: сортируется не текущее мультимножество, а неизменяемый массив возможных координат из операций +.
  2. Исправлено: значения из запросов ? x не обязаны входить в coordinate compression.
  3. Уточнено: лист хранит не только количество, а полный вклад coords[i] * count[i].
  4. Уточнено: граница запроса задаётся upper_bound, поэтому естественный диапазон — полуинтервал \(\bigl[0, k\bigr)\).
  5. Исправлено: одной бинарной сортировки недостаточно для дешёвой вставки в vector; линейный сдвиг исчезает только после назначения постоянных сжатых индексов.
  6. Добавлено: арифметика суммы должна выполняться в long long.
