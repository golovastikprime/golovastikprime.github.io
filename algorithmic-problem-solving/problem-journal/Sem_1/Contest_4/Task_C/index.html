Семестр 1 · Контест 4

Задача C — Splay tree: сумма на отрезке

Accepted · C++ · 24 июля 2026

Главная идея решения — хранить сумму поддерева и двумя Split изолировать ключи из требуемого диапазона.

Результат

Статус

Accepted. Все тесты пройдены.

Условие

Краткое условие

Изначально множество целых чисел \(S\) пусто. Требуется обрабатывать два вида запросов:

  • + x — добавить число \(x\) в множество; повторная вставка ничего не меняет;
  • ? l r — вывести сумму всех \(x\in S\), для которых \(l\le x\le r\).

Если операция + x идёт непосредственно после запроса суммы с ответом \(y\), то фактически вставляется

\[ (x+y)\bmod 10^9. \]

Поэтому операции необходимо обрабатывать online: значение следующей вставки может зависеть от уже вычисленного ответа.

Подход

Ключевое наблюдение

В вершине бинарного дерева поиска можно хранить сумму всего её поддерева:

\[ \operatorname{sum}(v) = \operatorname{key}(v) +\operatorname{sum}(v.left) +\operatorname{sum}(v.right). \]

Тогда запрос суммы на отрезке сводится не к обходу всех подходящих вершин, а к выделению соответствующего поддерева двумя операциями Split.

Определим

\[ \operatorname{Split}(T,k)=(A,B), \]

где

\[ A=\{x\in T:x<k\}, \qquad B=\{x\in T:x\ge k\}. \]

Для запроса \([l,r]\):

  1. \((A,BC)=\operatorname{Split}(T,l)\);
  2. \((B,C)=\operatorname{Split}(BC,r+1)\);
  3. теперь \(B\) содержит в точности ключи из \([l,r]\);
  4. ответ равен \(\operatorname{sum}(B)\);
  5. дерево восстанавливается:
\[ T=\operatorname{Merge}\bigl(A,\operatorname{Merge}(B,C)\bigr). \]

Splay tree позволяет выполнять Split и Merge через подъём выбранной вершины в корень. Баланс явно не хранится: эффективность обеспечивается амортизированным анализом последовательности операций.

Структура данных

Что хранится в вершине

Для каждой настоящей вершины \(v\) хранятся:

  • value — ключ;
  • left_child, right_child — дети;
  • parent — родитель;
  • sum — сумма ключей поддерева;
  • size — число вершин в поддереве.

Используется служебная вершина dummy_root_. Корень активного дерева хранится в dummy_root_.left_child.

Основные инварианты

1. Инвариант BST

Для каждой настоящей вершины \(v\):

\[ \forall x\in v.left:\ x<v.value, \qquad \forall y\in v.right:\ v.value<y. \]

Неравенства строгие, потому что структура хранит множество, а не multiset.

2. Инвариант агрегатов

\[ \operatorname{size}(v) = 1+\operatorname{size}(v.left)+\operatorname{size}(v.right), \]
\[ \operatorname{sum}(v) = v.value+\operatorname{sum}(v.left)+\operatorname{sum}(v.right). \]

Для nullptr обе величины считаются равными нулю.

После любого изменения дочернего указателя агрегаты соответствующей вершины нужно пересчитать. Одних обновлений, выполненных ранее во время поворотов, недостаточно.

3. Инвариант активного дерева

Перед вызовом SplayRotate:

dummy_root_.left_child == root;
root == nullptr || root->parent == &dummy_root_;

Если после Split одновременно существуют несколько отдельных деревьев, то перед splay одного из них оно сначала делается активным с помощью ActivateTree.

4. Инвариант родительских указателей

Для каждого ребра \(v\to u\):

u->parent == v

Корни двух деревьев, возвращённых Split, не должны оставаться связанными ни дочерним, ни родительским указателем.

5. Инвариант множества

Каждый ключ присутствует не более одного раза. Если при вставке ключ уже найден, новая вершина не создаётся; найденная вершина только поднимается в корень.

Механика

Обычный поворот

Правый поворот

Пусть \(v\) — левый ребёнок \(p\). Обозначим поддеревья:

\[ v.left=A,\qquad v.right=B,\qquad p.right=C. \]

До поворота порядок ключей имеет вид

\[ A<v<B<p<C. \]

После правого поворота:

\[ v.left=A,\qquad v.right=p,\qquad p.left=B,\qquad p.right=C. \]

Следовательно, порядок ключей остаётся

\[ A<v<B<p<C, \]

то есть инвариант BST сохраняется.

Помимо дочерних указателей необходимо:

  1. сделать \(v\) ребёнком прежнего родителя \(p\);
  2. установить p->parent = v;
  3. если \(B\ne\varnothing\), установить B->parent = p;
  4. присоединить \(v\) к прежнему родителю \(g\) вершины \(p\).

После поворота \(p\) становится ребёнком \(v\), поэтому агрегаты обновляются снизу вверх:

UpdateSize(p);
UpdateSum(p);
UpdateSize(v);
UpdateSum(v);

Если сначала пересчитать \(v\), вычисление использует ещё не обновлённые агрегаты \(p\).

Левый поворот

Левый поворот полностью симметричен. Если \(v\) — правый ребёнок \(p\), то левое поддерево \(v\) переносится в p->right_child, после чего \(p\) становится левым ребёнком \(v\).

Направление определяется положением поднимаемой вершины:

if (parent->left_child == v) {
  RotateRight(v);
} else {
  RotateLeft(v);
}

Механика

Splay: подъём вершины в корень

Пусть \(v\) — поднимаемая вершина, \(p\) — её родитель, \(g\) — родитель \(p\).

Zig

Если \(p\) уже является корнем активного дерева, выполняется один поворот между \(v\) и \(p\).

Zig-zig

Вершины \(v\) и \(p\) находятся с одной стороны от своих родителей:

  • обе являются левыми детьми; или
  • обе являются правыми детьми.

Сначала \(p\) поднимается над \(g\), затем \(v\) поднимается над \(p\):

Rotate(p);
Rotate(v);

Zig-zag

Вершины \(v\) и \(p\) находятся с разных сторон. Вершина \(v\) дважды поворачивается вверх:

Rotate(v);
Rotate(v);

После каждого случая глубина \(v\) уменьшается, а после завершения

v->parent == &dummy_root_;

и dummy_root_.left_child == v.

Операция дерева

LowerBound

LowerBound(key) ищет вершину с минимальным ключом, не меньшим key.

Во время обычного спуска по BST поддерживается кандидат:

  • если current->value >= key, текущая вершина подходит, но слева может быть меньший подходящий ключ;
  • иначе ответ может находиться только справа.

Если кандидат найден, Split поднимает его в корень. Если кандидата нет, все ключи меньше key; последняя посещённая вершина всё равно поднимается, чтобы сохранить splay-свойство доступа.

Важно: dummy_root_ не является Node. Функцию GetValue можно вызывать только для настоящих вершин дерева.

Доказательство

Корректность Split

Рассмотрим

\[ (A,B)=\operatorname{Split}(T,key). \]

Случай 1: LowerBound(key) существует

Пусть

\[ v=\min\{x\in T:x\ge key\}. \]

После SplayRotate(v) вершина \(v\) находится в корне.

По инварианту BST все ключи левого поддерева меньше \(v\). Среди них не может быть ключа \(x\ge key\), иначе \(x<v\) был бы меньшим подходящим кандидатом, что противоречит выбору \(v\). Поэтому

\[ \forall x\in v.left:\ x<key. \]

Вершина \(v\) и всё её правое поддерево имеют ключи не меньше key. Значит, после отсоединения v->left_child получаются именно требуемые множества:

\[ A=\{x:x<key\},\qquad B=\{x:x\ge key\}. \]

После отсоединения:

  • B->left_child устанавливается в nullptr;
  • корень \(A\), если он существует, получает родителя &dummy_root_;
  • size и sum корня \(B\) пересчитываются.

Случай 2: LowerBound(key) не существует

Тогда для всех \(x\in T\) выполнено \(x<key\), поэтому

\[ \operatorname{Split}(T,key)=(T,\varnothing). \]

Активный корень dummy_root_.left_child обнуляется, поскольку правая часть, с которой должна работать следующая операция, пуста.

Следовательно, Split корректен в обоих случаях.

Доказательство

Корректность Merge

Операция

\[ \operatorname{Merge}(L,R) \]

вызывается при условии

\[ \forall x\in L,\ \forall y\in R:\ x<y. \]

Если одно дерево пусто, результатом является второе дерево, которое сразу делается активным.

Пусть оба дерева непусты. Сначала активируется \(L\), затем находится

\[ v=\max(L) \]

и поднимается в корень.

У \(v\) не может быть правого ребёнка: в \(L\) нет ключа больше максимума. Поэтому \(R\) можно целиком присоединить как правое поддерево \(v\). По предусловию все ключи \(R\) больше \(v\), следовательно, инвариант BST сохраняется.

После присоединения обязательно выполняются

UpdateSize(v);
UpdateSum(v);

поскольку сам указатель v->right_child был изменён уже после завершения SplayRotate.

Доказательство

Корректность вставки

Обычный спуск по BST находит:

  • уже существующую вершину с таким ключом; или
  • nullptr в единственной допустимой позиции для новой вершины.

В первом случае множество не меняется, а найденная вершина поднимается в корень.

Во втором случае создаётся лист с

\[ \operatorname{size}=1,\qquad \operatorname{sum}=value, \]

после чего он присоединяется к найденному родителю и поднимается в корень. Повороты пересчитывают агрегаты снизу вверх, поэтому после завершения агрегаты всего дерева снова корректны.

Доказательство

Корректность запроса суммы

После первого разделения

\[ (A,BC)=\operatorname{Split}(T,l) \]

имеем

\[ A=\{x:x<l\},\qquad BC=\{x:x\ge l\}. \]

После второго разделения

\[ (B,C)=\operatorname{Split}(BC,r+1) \]

имеем

\[ B=\{x:l\le x<r+1\}=\{x:l\le x\le r\}, \]
\[ C=\{x:x>r\}. \]

По инварианту агрегатов GetSum(B) равен сумме всех и только тех ключей, которые принадлежат \([l,r]\).

Порядок между частями:

\[ \forall a\in A,\ \forall b\in B,\ \forall c\in C: \qquad a<b<c. \]

Поэтому оба последующих Merge допустимы и восстанавливают исходное множество. Следовательно, RangeSum(left, right) возвращает правильный ответ и не меняет множество хранимых ключей.

Корректность

Online-преобразование вставки

Одного значения последней суммы недостаточно: нужно помнить тип предыдущей операции.

В коде используется флаг last_was_insert:

  • после + устанавливается true;
  • после ? устанавливается false;
  • если при обработке + флаг равен false, вставляется \((x+y)\bmod 10^9\);
  • иначе вставляется исходный \(x\).

Обновление этого флага является частью корректности алгоритма, а не технической деталью ввода.

Анализ

Оценка сложности

Один поворот работает за \(O(1)\).

Один конкретный вызов SplayRotate в худшем случае может выполнить \(O(n)\) поворотов. Поэтому splay tree не гарантирует worst-case \(O(\log n)\) на каждую отдельную операцию.

По access lemma суммарная стоимость последовательности splay-операций логарифмична амортизированно. В частности:

  • Insert — \(O(\log n)\) амортизированно;
  • Split — \(O(\log n)\) амортизированно;
  • Merge — \(O(\log n)\) амортизированно;
  • RangeSum использует константное число Split и Merge, поэтому также работает за \(O(\log n)\) амортизированно.

Для \(q\) запросов:

\[ T(q)=O(q\log q) \]

амортизированно.

Память:

\[ O(n), \]

где \(n\) — число различных вставленных ключей. Рекурсивный Clear использует дополнительно \(O(h)\) стековой памяти, где \(h\) — текущая высота дерева.

Разбор ошибок

Основные ошибки при реализации

1. Неверный выбор направления поворота

Направление определяется положением \(v\) относительно родителя:

  • \(v\) слева — правый поворот;
  • \(v\) справа — левый поворот.

2. Неправильный пересчёт после поворота

После поворота сначала пересчитывается бывший родитель, затем новая вершина поддерева. Кроме того, UpdateSum(v) нельзя случайно заменить повторным UpdateSize(v).

3. Две части Split оставались связанными

Недостаточно вернуть

{lower_bound->left_child, lower_bound}

Нужно физически отсоединить левое поддерево и исправить его parent.

4. Служебная вершина использовалась как пустое дерево

Пустое дерево представляется только nullptr. Возврат &dummy_root_ как обычной вершины приводит к некорректному static_cast<Node*> и undefined behavior.

5. Терялся инвариант активного дерева

После Split поле dummy_root_.left_child могло указывать не на то дерево, над которым выполнялся следующий splay. Поэтому перед работой с отдельным деревом нужен ActivateTree, включая граничные случаи Merge с nullptr.

6. Агрегаты не обновлялись после Merge

Повороты обновляют состояние до присоединения правого дерева. После

maximum->right_child = right_tree;

структура снова изменилась, поэтому агрегаты корня нужно пересчитать ещё раз.

7. Новая вершина создавалась внутри цикла поиска

Сначала цикл должен полностью найти nullptr, и лишь затем можно присоединять новый лист. Иначе пустое дерево ничего не вставляет, а в непустом дереве можно перезаписать существующее поддерево.

8. Несогласованные типы и имена функций

Сигнатура определения Insert должна совпадать с объявлением, а обращение к ключу должно использовать существующую функцию GetValue.

9. Не обновлялся тип последней операции

Если last_was_insert никогда не менять, online-преобразование после запроса не выполняется. Это давало неверный ответ уже на примере:

4
+ 1
? 0 2
+ 2
? 2 2

После первого ответа \(y=1\) должна вставиться \(3\), а не \(2\).

Корневая причина большинства ошибок

Структурная операция над деревом должна завершаться восстановлением трёх связанных инвариантов:

  1. корректны дочерние и родительские указатели;
  2. корректен активный корень;
  3. корректны агрегаты изменённых вершин.

Проверка только формы BST недостаточна.

Перенос идеи

Как распознать похожую задачу

Характерные признаки:

  • поддерживается динамическое множество упорядоченных ключей;
  • запрос зависит от диапазона значений ключей, а не от времени их вставки;
  • нужно хранить агрегат поддерева: сумму, количество, минимум или другую ассоциативную величину;
  • диапазон удобно выделяется двумя разрезами по ключу;
  • после запроса части структуры нужно быстро соединить обратно;
  • операции должны обрабатываться online;
  • допустима амортизированная, а не обязательно worst-case гарантия.

Общий паттерн:

\[ \text{augmented BST} +\text{Split/Merge} +\text{subtree aggregate}. \]

Близкие альтернативы:

  • AVL/Red-Black tree с суммами поддеревьев;
  • randomized treap с Split/Merge;
  • динамическое дерево отрезков по большому диапазону координат.

Splay tree особенно естественен, когда Split и Merge строятся через подъём граничной вершины в корень.

Post-Accepted

Финальный код

В приведённой ниже записи сделаны только технические правки, не меняющие принятый алгоритм: удалены неиспользуемые заголовки, явно подключён <utility>, а параметр LowerBound приведён к общему типу Type.

#include <iostream>
#include <utility>

class Splay {
  using Type = long long;

  struct BaseNode {
    Type sum{0};
    Type size{0};

    BaseNode() = default;
    virtual ~BaseNode() = default;
    BaseNode(Type sum, Type size) : sum(sum), size(size) {}

    BaseNode* parent = this;
    BaseNode* left_child = nullptr;
    BaseNode* right_child = nullptr;
  };

  struct Node : BaseNode {
    explicit Node(Type value) : BaseNode(value, 1), value(value) {}

    Type value;
  };

  static Type GetSum(BaseNode* v) {
    if (v == nullptr) {
      return 0;
    }
    return v->sum;
  }

  static Type GetSize(BaseNode* v) {
    if (v == nullptr) {
      return 0;
    }
    return v->size;
  }

  static Type GetValue(BaseNode* v) {
    return static_cast<Node*>(v)->value;
  }

  static void UpdateSum(BaseNode* v) {
    v->sum =
        GetValue(v) + GetSum(v->left_child) + GetSum(v->right_child);
  }

  static void UpdateSize(BaseNode* v) {
    v->size =
        1 + GetSize(v->left_child) + GetSize(v->right_child);
  }

 public:
  Splay() = default;

  ~Splay() { Clear(dummy_root_.left_child); }

  void Insert(Type value) {
    BaseNode* current = dummy_root_.left_child;
    BaseNode* parent = &dummy_root_;
    bool was_left = true;

    while (current != nullptr) {
      if (GetValue(current) == value) {
        SplayRotate(current);
        return;
      }

      parent = current;
      if (GetValue(current) < value) {
        current = current->right_child;
        was_left = false;
      } else {
        current = current->left_child;
        was_left = true;
      }
    }

    BaseNode* new_node = new Node(value);
    new_node->parent = parent;

    if (was_left) {
      parent->left_child = new_node;
    } else {
      parent->right_child = new_node;
    }

    SplayRotate(new_node);
  }

  Type RangeSum(Type left, Type right) {
    auto [a, bc] = Split(left);
    auto [b, c] = Split(right + 1);

    Type result = GetSum(b);

    BaseNode* restored_bc = Merge(b, c);
    Merge(a, restored_bc);

    return result;
  }

 private:
  BaseNode dummy_root_;

  void Clear(BaseNode* v) {
    if (v == nullptr) {
      return;
    }

    Clear(v->left_child);
    Clear(v->right_child);
    delete v;
  }

  static void RotateRight(BaseNode* v) {
    BaseNode* parent = v->parent;
    BaseNode* right_child = v->right_child;

    v->right_child = parent;
    parent->left_child = right_child;
    parent->parent = v;

    if (right_child != nullptr) {
      right_child->parent = parent;
    }
  }

  static void RotateLeft(BaseNode* v) {
    BaseNode* parent = v->parent;
    BaseNode* left_child = v->left_child;

    v->left_child = parent;
    parent->right_child = left_child;
    parent->parent = v;

    if (left_child != nullptr) {
      left_child->parent = parent;
    }
  }

  static void Rotate(BaseNode* v) {
    BaseNode* parent = v->parent;
    BaseNode* granny = parent->parent;
    bool was_left = granny->left_child == parent;

    if (parent->left_child == v) {
      RotateRight(v);
    } else {
      RotateLeft(v);
    }

    v->parent = granny;
    if (was_left) {
      granny->left_child = v;
    } else {
      granny->right_child = v;
    }

    UpdateSize(parent);
    UpdateSum(parent);
    UpdateSize(v);
    UpdateSum(v);
  }

  void SplayRotate(BaseNode* v) {
    while (v->parent != &dummy_root_) {
      BaseNode* parent = v->parent;
      BaseNode* granny = parent->parent;

      bool is_zig_zig =
          (granny->left_child == parent &&
           parent->left_child == v) ||
          (granny->right_child == parent &&
           parent->right_child == v);

      if (granny == &dummy_root_) {
        Rotate(v);
      } else if (is_zig_zig) {
        Rotate(parent);
        Rotate(v);
      } else {
        Rotate(v);
        Rotate(v);
      }
    }
  }

  BaseNode* LowerBound(Type x) {
    BaseNode* current = dummy_root_.left_child;
    BaseNode* candidate = nullptr;
    BaseNode* last = &dummy_root_;

    while (current != nullptr) {
      last = current;

      if (GetValue(current) >= x) {
        candidate = current;
        current = current->left_child;
      } else {
        current = current->right_child;
      }
    }

    SplayRotate(last);
    return candidate;
  }

  static BaseNode* Maximum(BaseNode* v) {
    if (v == nullptr) {
      return nullptr;
    }

    while (v->right_child != nullptr) {
      v = v->right_child;
    }

    return v;
  }

  std::pair<BaseNode*, BaseNode*> Split(Type key) {
    BaseNode* lower_bound = LowerBound(key);

    if (lower_bound == nullptr) {
      BaseNode* left_tree = dummy_root_.left_child;
      dummy_root_.left_child = nullptr;
      return {left_tree, nullptr};
    }

    SplayRotate(lower_bound);

    BaseNode* left_tree = lower_bound->left_child;
    lower_bound->left_child = nullptr;

    if (left_tree != nullptr) {
      left_tree->parent = &dummy_root_;
    }

    UpdateSize(lower_bound);
    UpdateSum(lower_bound);

    return {left_tree, lower_bound};
  }

  void ActivateTree(BaseNode* tree) {
    dummy_root_.left_child = tree;

    if (tree != nullptr) {
      tree->parent = &dummy_root_;
    }
  }

  BaseNode* Merge(BaseNode* left_tree, BaseNode* right_tree) {
    if (left_tree == nullptr) {
      ActivateTree(right_tree);
      return right_tree;
    }

    if (right_tree == nullptr) {
      ActivateTree(left_tree);
      return left_tree;
    }

    ActivateTree(left_tree);

    BaseNode* maximum = Maximum(left_tree);
    SplayRotate(maximum);

    maximum->right_child = right_tree;
    right_tree->parent = maximum;

    UpdateSize(maximum);
    UpdateSum(maximum);

    return maximum;
  }
};

int main() {
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);

  const long long cMod = 1'000'000'000LL;

  int query_count;
  std::cin >> query_count;

  Splay tree;
  bool last_was_insert = true;
  long long last_sum = 0;

  for (int i = 0; i < query_count; ++i) {
    char command;
    std::cin >> command;

    if (command == '+') {
      long long x;
      std::cin >> x;

      if (!last_was_insert) {
        x = (x + last_sum) % cMod;
      }

      tree.Insert(x);
      last_was_insert = true;
    } else if (command == '?') {
      long long left;
      long long right;
      std::cin >> left >> right;

      last_sum = tree.RangeSum(left, right);
      std::cout << last_sum << '\n';
      last_was_insert = false;
    }
  }
}
