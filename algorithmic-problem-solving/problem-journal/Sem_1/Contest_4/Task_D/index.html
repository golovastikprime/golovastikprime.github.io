Семестр 1 · Контест 4

Задача D — Заправки на трассах

Accepted · C++ · 24 июля 2026

События сортируются по координате, а последовательность обновлений диапазона хранится в lazy segment tree как композиция преобразований.

Результат

Статус

Accepted. Основная техника — сортировка событий и lazy propagation; lazy-тег рассматривается как элемент моноида преобразований.

Условие

Краткое условие

Есть трассы с номерами

\[ 0,1,\ldots,h. \]

Длина каждой трассы равна \(w\). Заправка описывается тройкой \((x,l,r)\), где \(x\) — координата, а \([l,r]\) — включительный диапазон пересекаемых трасс.

Для каждой трассы требуется найти минимальный объём бака. Он равен максимальному расстоянию:

  • от начала трассы до первой заправки;
  • между соседними заправками;
  • от последней заправки до конца трассы.

Если заправок нет, ответ равен \(w\).

Отправная точка

Наивное решение

После сортировки заправок по координате \(x\) для каждой трассы достаточно хранить:

  • last — координату последней обработанной заправки;
  • answer — максимальный завершённый промежуток.

При обработке заправки в точке \(x\):

\[ \text{answer}\leftarrow\max(\text{answer},x-\text{last}), \qquad \text{last}\leftarrow x. \]

Но обновление всех трасс из \([l,r]\) может затронуть \(\Theta(h)\) объектов, поэтому худшая оценка равна \(O(nh)\).

Подход

Ключевое наблюдение

Состояния трасс различаются, но ко всем трассам диапазона применяется одно преобразование. Обозначим состояние одной трассы через \((M,p)\), где \(p\) — последняя заправка, а \(M\) — максимальный завершённый промежуток.

Заправка в точке \(x\) действует так:

\[ (M,p)\longmapsto \bigl(\max(M,x-p),x\bigr). \]

Для последовательности \(x_1\le x_2\le\ldots\le x_k\) действие имеет вид

\[ (M,p)\longmapsto \left( \max\left(M,x_1-p,x_2-x_1,\ldots,x_k-x_{k-1}\right), x_k \right). \]

Всю последовательность можно сжать до тега \((a,b,t)\):

  • \(a=x_1\) — первая заправка;
  • \(b=x_k\) — последняя заправка;
  • \(t=\max_{2\le i\le k}(x_i-x_{i-1})\) — максимальный внутренний промежуток.

Тег действует на произвольное состояние по формуле

\[ (M,p)\longmapsto \bigl(\max(M,a-p,t),b\bigr). \]

Алгебра тегов

Композиция тегов

Пусть \(A=(a_1,b_1,t_1)\) был обработан раньше \(B=(a_2,b_2,t_2)\). Тогда композиция «сначала \(A\), затем \(B\)» равна

\[ A*B= \left( a_1, b_2, \max(t_1,t_2,a_2-b_1) \right). \]

Величина \(a_2-b_1\) — промежуток между двумя группами.

Почему формула верна

\[ (M,p) \xrightarrow{A} \bigl(\max(M,a_1-p,t_1),b_1\bigr) \xrightarrow{B} \left( \max(M,a_1-p,t_1,a_2-b_1,t_2), b_2 \right). \]

Это в точности действие объединённого тега.

Нейтральный элемент

Пустую последовательность кодируем тегом

\[ E=(-1,-1,-1). \]

Для него отдельно определяем \(E*A=A\) и \(A*E=A\). Подставлять маркер в обычную формулу нельзя.

Ассоциативность и порядок

Операция * описывает композицию преобразований, поэтому она ассоциативна:

\[ (A*B)*C=A*(B*C). \]

Теги с операцией * и элементом \(E\) образуют моноид. Операция некоммутативна, поэтому хронологический порядок принципиален.

Структура данных

Lazy propagation

Вершина \(v\) отвечает за диапазон трасс \(I_v\). Значение lazy[v] хранит в правильном хронологическом порядке композицию обновлений, которые полностью покрыли этот диапазон, но ещё не были переданы детям.

Полное покрытие

\[ \text{lazy}[v]\leftarrow \text{lazy}[v]*\text{newTag}. \]

Старый тег стоит слева, потому что применяется раньше нового.

Частичное покрытие

Перед спуском обязательно выполняется Push. Если у ребёнка хранится старый тег \(C\), а у родителя — более поздний тег \(A\), ребёнок должен получить

\[ C*A. \]

Если сначала добавить частичное обновление \(B\), а потом протолкнуть родителя, получится неверный порядок \(C*B*A\) вместо \(C*A*B\).

Почему Pull не нужен

Промежуточных запросов по диапазонам нет. Нужны только итоговые состояния листьев, поэтому агрегат вершины и пересчёт родителя по детям не требуются.

Финализация

Получение ответов

После всех обновлений один DFS проталкивает теги до листьев. Если итоговый тег трассы равен \((a,b,t)\), ответ равен

\[ F=\max(a,t,w-b). \]

Здесь учитываются начальный, внутренний и конечный промежутки. Для тега \(E\) заправок нет, поэтому \(F=w\).

Доказательство

Корректность алгоритма

Лемма 1. Тег содержит достаточно информации

Первая новая заправка завершает промежуток длины \(a-p\), максимум внутренних промежутков равен \(t\), а последней заправкой становится \(b\). Поэтому тег переводит состояние в \(\bigl(\max(M,a-p,t),b\bigr)\); другие сведения о последовательности не влияют на результат.

Лемма 2. Композиция тегов корректна

В объединённой последовательности первая координата равна \(a_1\), последняя — \(b_2\), а максимальный внутренний промежуток является максимумом из \(t_1\), \(t_2\) и промежутка между группами \(a_2-b_1\).

Лемма 3. Инвариант lazy propagation сохраняется

При полном покрытии новый тег добавляется справа: \(\text{old}*\text{new}\). При частичном покрытии дети сначала получают свою старую историю, затем более позднюю историю родителя. После сброса родителя рекурсивное обновление добавляется ещё позже.

Теорема

После финального DFS каждый лист содержит все и только те заправки, которые пересекают соответствующую трассу, в неубывающем порядке координаты. Тег правильно хранит первую, последнюю и максимальный внутренний промежуток, а формула \(\max(a,t,w-b)\) учитывает все промежутки без заправок. Поэтому найденный объём бака необходим и достаточен.

Оценка

Сложность

Сортировка занимает \(O(n\log n)\), все range-update — \(O(n\log(h+1))\), финальный DFS — \(O(h)\).

\[ O\bigl(n\log n+n\log(h+1)+h\bigr). \]

Память:

\[ O(n+h). \]

Разбор ошибки

Количество трасс и границы дерева

Трассы нумеруются от \(0\) до \(h\), поэтому существует \(h+1\) трасса. Диапазоны \([l,r]\) уже нулевые, вычитать единицу не нужно.

Ошибочный код:

SegmentTree tree(h);

Правильно:

SegmentTree tree(h + 1);

Внутреннее дерево построено на включительном диапазоне \([0,N_-1]\), поэтому обёртка вызывает

Update(1, 0, N_ - 1, ql, qr, item);

Важно различать максимальный номер трассы \(h\), количество трасс \(h+1\) и округлённое до степени двойки число листьев \(N_\).

Перенос идеи

Признаки похожих задач

Подход стоит проверять, если:

  1. события можно отсортировать по времени или координате;
  2. событие одинаково воздействует на диапазон объектов;
  3. состояния объектов различаются, поэтому простое присваивание диапазону не подходит;
  4. последовательность воздействий сжимается до малого набора параметров;
  5. сжатые описания можно ассоциативно компоновать;
  6. ответы нужны после всех обновлений или структура умеет поддерживать нужные агрегаты.

Представить range-update не как новое значение, а как преобразование. Затем найти компактное представление композиции преобразований и хранить его как lazy-тег.

Реализация

Финальный код

#include <algorithm>
#include <iostream>
#include <vector>

struct Item {
  int a;
  int b;
  int t;

  static Item Identity() { return {-1, -1, -1}; }

  bool operator==(const Item& rhs) const {
    return a == rhs.a && b == rhs.b && t == rhs.t;
  }
};

Item operator*(const Item& lhs, const Item& rhs) {
  if (lhs == Item::Identity()) {
    return rhs;
  }

  if (rhs == Item::Identity()) {
    return lhs;
  }

  return {
      lhs.a,
      rhs.b,
      std::max(std::max(lhs.t, rhs.t), rhs.a - lhs.b),
  };
}

class SegmentTree {
 public:
  explicit SegmentTree(int size) : size_(size) {
    while (N_ < size_) {
      N_ *= 2;
    }
    lazy_.assign(N_ * 2, Item::Identity());
  }

  void Update(int ql, int qr, const Item& item) {
    Update(1, 0, N_ - 1, ql, qr, item);
  }

  void PushAll() { PushAll(1, 0, N_ - 1); }

  std::vector<Item> GetItems() const {
    std::vector<Item> result(size_);

    for (int i = 0; i < size_; ++i) {
      result[i] = lazy_[N_ + i];
    }

    return result;
  }

 private:
  void Update(int v, int left, int right, int ql, int qr,
              const Item& item) {
    if (right < ql || qr < left) {
      return;
    }

    if (ql <= left && right <= qr) {
      Apply(v, item);
      return;
    }

    Push(v, left, right);

    int mid = left + (right - left) / 2;
    Update(LeftChild(v), left, mid, ql, qr, item);
    Update(RightChild(v), mid + 1, right, ql, qr, item);
  }

  void Apply(int v, const Item& item) {
    lazy_[v] = lazy_[v] * item;
  }

  void Push(int v, int left, int right) {
    if (left == right || lazy_[v] == Item::Identity()) {
      return;
    }

    Apply(LeftChild(v), lazy_[v]);
    Apply(RightChild(v), lazy_[v]);
    lazy_[v] = Item::Identity();
  }

  void PushAll(int v, int left, int right) {
    if (left == right) {
      return;
    }

    Push(v, left, right);

    int mid = left + (right - left) / 2;
    PushAll(LeftChild(v), left, mid);
    PushAll(RightChild(v), mid + 1, right);
  }

  static int LeftChild(int v) { return 2 * v; }
  static int RightChild(int v) { return 2 * v + 1; }

  std::vector<Item> lazy_;
  int N_{1};
  int size_{};
};

struct GasStation {
  int x;
  int l;
  int r;
};

bool operator<(const GasStation& lhs, const GasStation& rhs) {
  return lhs.x < rhs.x;
}

int main() {
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);

  int n;
  int h;
  int w;
  std::cin >> n >> h >> w;

  std::vector<GasStation> stations(n);
  for (int i = 0; i < n; ++i) {
    std::cin >> stations[i].x
             >> stations[i].l
             >> stations[i].r;
  }

  std::sort(stations.begin(), stations.end());

  SegmentTree tree(h + 1);

  for (const auto& [x, l, r] : stations) {
    tree.Update(l, r, {x, x, 0});
  }

  tree.PushAll();
  std::vector<Item> result = tree.GetItems();

  for (const auto& [a, b, t] : result) {
    if (a == -1) {
      std::cout << w << '\n';
    } else {
      std::cout << std::max(std::max(a, t), w - b) << '\n';
    }
  }
}

Вывод

Итог

Главная идея — хранить в lazy-теге не состояние трасс, а компактное преобразование их состояний. Ассоциативная композиция сохраняет хронологию событий и позволяет обновлять целые диапазоны за логарифмическое время.
