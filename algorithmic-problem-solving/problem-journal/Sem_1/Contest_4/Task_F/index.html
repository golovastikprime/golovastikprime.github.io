Семестр 1 · Контест 4

Задача F — Counting Nested Segments

Accepted · C++ · 20 июля 2026

В этой задаче сортировка обеспечивает L′ ≤ L, а дерево отрезков проверяет R′ ≥ R.

Условие

Задача

Дан набор из n отрезков на прямой. Два отрезка называются вложенными, если они не равны и один из них содержит другой. Требуется найти число пар вложенных отрезков.

Неравенство отрезков здесь означает, что пары их границ не совпадают полностью:

(Li, Ri) ≠ (Lj, Rj).

Совпадение только левой или только правой границы не исключает вложенность.

Формат ввода

В первой строке дано целое число n:

1 ≤ n ≤ 3 · 105.

В следующих n строках даны пары целых чисел li, ri, задающие границы отрезков:

0 ≤ li ≤ ri ≤ 109.

Формат вывода

Вывести число пар вложенных отрезков.

Подход

Ключевое наблюдение

Отрезок [L′, R′] содержит [L, R] тогда и только тогда, когда

L′ ≤ L, R′ ≥ R.

Здесь есть два монотонных условия по двум координатам. Отсортируем отрезки по L по возрастанию, а при равных L — по R по убыванию. Тогда для текущего отрезка условие L′ ≤ L уже обеспечено порядком обработки. Среди ранее обработанных отрезков остаётся посчитать только те, для которых R′ ≥ R.

Правые границы сжимаются в массив

rights = [r0 < r1 < … < rk−1].

Если p = pos(R), то условие R′ ≥ R эквивалентно попаданию сжатой координаты R′ в суффикс [p, k). Количество таких ранее обработанных отрезков поддерживает дерево отрезков.

Полностью одинаковые пары (L, R) объединяются в класс мощности c. Для класса сначала выполняется запрос, а только затем все c его элементов добавляются в дерево. Поэтому одинаковые отрезки не учитывают друг друга.

Для текущего класса:

q = Query(p, k),

answer += q · c,

после чего выполняется Add(p, c).

Структура данных

Инвариант структуры данных

Перед обработкой очередного класса в листе с индексом j хранится количество уже обработанных отрезков, правая граница которых имеет сжатый индекс j. Во внутренней вершине хранится сумма по соответствующему диапазону.

Следовательно, запрос суммы на [p, k) возвращает число уже обработанных отрезков с правой границей не меньше R.

Почему это работает

Доказательство корректности

Лемма 1. Каждая посчитанная пара допустима

Пусть при обработке класса [L, R] запрос учёл ранее обработанный отрезок [L′, R′].

Из порядка сортировки следует L′ ≤ L. Поскольку сжатая координата R′ попала в суффикс [p, k), имеем R′ ≥ R. Поэтому

[L, R] ⊆ [L′, R′].

Полное равенство невозможно: весь класс одинаковых отрезков (L, R) добавляется в дерево только после запроса.

Лемма 2. Каждая допустимая пара будет посчитана

Пусть отличный от текущего отрезок [L′, R′] содержит [L, R]. Тогда

L′ ≤ L, R′ ≥ R.

Если L′ < L, то [L′, R′] обработан раньше из-за сортировки по левой границе. Если L′ = L, то из отличия отрезков и вложенности следует R′ > R; при равных левых границах больший правый конец также расположен раньше.

Таким образом, содержащий отрезок уже находится в дереве. Из R′ ≥ R следует pos(R′) ≥ p, поэтому запрос [p, k) обязательно его учтёт.

Теорема

По лемме 1 алгоритм не считает недопустимые пары, а по лемме 2 считает каждую допустимую пару. Элементы одного класса не считаются между собой благодаря порядку Query → Add. Каждая допустимая пара учитывается ровно один раз — при обработке внутреннего отрезка. Следовательно, полученный ответ точен.

Оценка ресурсов

Сложность

Сортировка отрезков и правых границ занимает O(n log n). Каждый класс выполняет один запрос и одно обновление за O(log k) ⊆ O(log n). Поэтому

T(n) = O(n log n), S(n) = O(n).

Ответ может иметь порядок C(n, 2), поэтому для ответа и произведения q · c нужен тип long long.

История поиска

Главный тупик

Было понятно, как сортировкой контролировать левые границы, но не было ясно, как эффективно учитывать правые границы.

Переход состоял в разделении двух условий:

  • сортировка фиксирует условие по одной координате;
  • структура данных поддерживает условие по второй координате.

Отдельного внимания потребовали равенства: одинаковые левые границы, одинаковые правые границы и полностью совпадающие отрезки.

Перенос идеи

Признаки похожих задач

Стоит проверять сочетание сортировки и структуры данных, когда:

  • объект задаётся несколькими координатами;
  • подходящая пара определяется несколькими неравенствами или другими монотонными условиями;
  • сортировка по одной координате автоматически обеспечивает одно условие для ранее обработанных объектов;
  • оставшееся условие сводится к запросу количества, суммы, минимума или максимума на префиксе либо суффиксе;
  • значения координат велики, но важен лишь их относительный порядок, поэтому применимо координатное сжатие;
  • равные координаты требуют специального tie-breaking или групповой обработки.

В этой задаче сортировка обеспечивает L′ ≤ L, а дерево отрезков проверяет R′ ≥ R.
