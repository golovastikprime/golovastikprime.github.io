Семестр 1 · Контест 4

Задача B — Splay tree с порядковыми статистиками

Accepted · C++ · 23 июля 2026

Ответы на запросы по ключам определяются BST-порядком.

Условие

Условие

Изначально множество целых чисел \(S\) пусто. Требуется обрабатывать команды:

  • insert x — добавить \(x\) в множество; повторная вставка ничего не меняет;
  • delete x — удалить \(x\), если он существует;
  • exists x — вывести true, если \(x\in S\), иначе false;
  • next x — вывести минимальный элемент множества, строго больший \(x\), либо none;
  • prev x — вывести максимальный элемент множества, строго меньший \(x\), либо none;

  • kth k — вывести элемент с нулевым рангом \(k\) в отсортированном множестве, либо none, если

    \[ k<0 \quad\text{или}\quad k\ge |S|. \]

Команды читаются до конца файла.

Мотивация

Почему недостаточно обычного BST

Все операции можно реализовать в binary search tree за \(O(h)\), где \(h\) — текущая высота дерева. Однако обычное BST может выродиться в цепочку.

Например, последовательность

insert 1
insert 2
insert 3
...
insert n

может создать дерево высоты \(\Theta(n)\). Тогда поиск, вставка и удаление в худшем случае также потребуют \(\Theta(n)\) времени.

В splay tree после доступа выбранная вершина поднимается в корень серией поворотов. Дерево не поддерживает явного ограничения на высоту, поэтому одна операция всё ещё может стоить \(O(n)\). Однако любая последовательность операций имеет логарифмическую амортизированную стоимость на операцию.

Подход

Ключевое наблюдение

Ответы на запросы по ключам определяются BST-порядком. Для kth дополнительно нужен корректный размер каждого поддерева, а для самой реализации поворотов — согласованные родительские указатели. Для амортизированной эффективности после каждого поискового спуска нужно выполнить splay:

  • если искомая вершина найдена — поднять её;
  • если ключа нет — поднять последнюю посещённую вершину;
  • для next и prev сохранить кандидата для ответа, но поднять именно последнюю посещённую вершину;
  • после вставки поднять новую или уже существовавшую вершину;
  • перед удалением поднять найденную вершину в корень.

Последнее правило принципиально для амортизированной оценки. Поднять только кандидата next или prev недостаточно: кандидат может уже быть корнем, хотя сам поисковый путь прошёл через длинную цепочку. Тогда повторный такой же запрос снова стоил бы линейное время и не перестраивал бы пройденный путь.

Для операции kth дополнительно хранится размер каждого поддерева.

Структура данных

Хранимая информация

Каждая настоящая вершина хранит:

int size;
BaseNode* parent;
BaseNode* left_child;
BaseNode* right_child;
int value;

Поле

\[ size[v] \]

равно количеству настоящих вершин в поддереве \(v\).

Также используется фиктивная вершина dummy_root_:

dummy_root_.left_child

указывает на настоящий корень, а для непустого дерева выполняется

dummy_root_.left_child->parent == &dummy_root_;

Сентинел позволяет одинаково присоединять результат поворота как внутри дерева, так и на месте всего корня.

Инварианты

Инварианты структуры

После завершения каждой публичной операции выполняются следующие свойства.

1. BST-инвариант

Для каждой настоящей вершины \(v\):

\[ \forall u\in T_{\mathrm{left}}(v): \operatorname{key}(u)<\operatorname{key}(v), \]
\[ \forall u\in T_{\mathrm{right}}(v): \operatorname{key}(u)>\operatorname{key}(v). \]

Равные ключи не вставляются, поэтому дерево представляет множество.

2. Инвариант родительских указателей

Для каждого непустого ребра от \(v\) к ребёнку \(u\):

u->parent == v

Для настоящего корня:

root->parent == &dummy_root_

3. Инвариант размеров

Полагаем

\[ size(\varnothing)=0. \]

Для каждой настоящей вершины \(v\):

\[ size[v] = 1+size[v_{\mathrm{left}}]+size[v_{\mathrm{right}}]. \]

Новая вершина создаётся с size = 1.

4. Инвариант представляемого множества

Повороты не создают, не удаляют и не изменяют ключи. Множество ключей меняют только успешные insert и delete.

Механика

Один поворот

Функция Rotate(v) поднимает вершину \(v\) на один уровень. Обозначим:

  • \(p=v.\text{parent}\);
  • \(g=p.\text{parent}\);
  • \(B\) — промежуточное поддерево, которое переносится между \(v\) и \(p\).

Перед изменением связей обязательно сохраняется \(g\), поскольку после локального поворота p->parent уже изменится.

Если \(v\) — левый ребёнок

Выполняется правый поворот:

B = v->right_child;
v->right_child = p;
p->left_child = B;

и восстанавливаются обратные указатели:

p->parent = v;
if (B != nullptr) {
  B->parent = p;
}

До поворота inorder-порядок имеет вид

\[ A < v < B < p < C. \]

После поворота последовательность остаётся той же, поэтому BST-инвариант сохраняется.

Если \(v\) — правый ребёнок

Симметрично выполняется левый поворот:

B = v->left_child;
v->left_child = p;
p->right_child = B;

После локальной перестройки \(v\) присоединяется к прежнему родителю \(g\) с той же стороны, с которой раньше находился \(p\).

Порядок пересчёта размеров

После поворота сначала пересчитывается бывший родитель \(p\), затем новый корень поддерева \(v\):

UpdateSize(p);
UpdateSize(v);

Этот порядок необходим, поскольку новое поддерево \(v\) уже содержит поддерево \(p\).

Другие вершины не требуют пересчёта: состав их поддеревьев не изменился.

Самонастройка

Операция SplayRotate(v)

Пока \(v\) не стала настоящим корнем, рассматриваются её родитель \(p\) и дедушка \(g\).

Случай Положение Последовательность
zig \(p\) — настоящий корень Rotate(v)
zig-zig \(v\) и \(p\) оба левые или оба правые дети Rotate(p), затем Rotate(v)
zig-zag \(v\) и \(p\) расположены с разных сторон Rotate(v), затем ещё раз Rotate(v)

Условие zig-zig:

bool is_zig_zig =
    (g->left_child == p && p->left_child == v) ||
    (g->right_child == p && p->right_child == v);

В zig-zig порядок нельзя менять. Сначала \(p\) поднимается над \(g\), затем \(v\) поднимается над \(p\).

В zig-zag после первого Rotate(v) вершина \(v\) становится ребёнком \(g\). Поэтому второй вызов той же функции поднимает её ещё на один уровень.

После двойного шага глубина \(v\) уменьшается на два, а после zig — на один. Следовательно, цикл завершается с

v->parent == &dummy_root_

и \(v\) становится настоящим корнем.

Поиск

Поиск и последняя посещённая вершина

FindNode(x) возвращает пару:

{vertex, was_found}
  • если \(x\) найден, vertex указывает на него;
  • если \(x\) отсутствует, vertex указывает на последнюю посещённую вершину;
  • если дерево пусто, возвращается {nullptr, false}.

После поиска непустой vertex поднимается в корень независимо от успешности. Это не влияет на ответ, поскольку повороты сохраняют множество и inorder-порядок, но необходимо для стандартной амортизированной гарантии splay tree.

Операция дерева

Вставка

Вставка начинается как в обычном BST.

Во время спуска хранятся:

BaseNode* parent;
bool was_left;

Если равный ключ найден, новая вершина не создаётся, а существующая поднимается в корень.

Иначе в первое пустое место присоединяется новый лист:

BaseNode* new_node = new Node(value);
new_node->parent = parent;

После этого вызывается

SplayRotate(new_node);

Повороты пересчитывают размеры всех вершин, чьи поддеревья изменились.

Корректность вставки

Путь спуска однозначно определён сравнениями ключей. Новый ключ присоединяется в первое пустое место на этом пути, поэтому для всех его предков сохраняется BST-инвариант.

В дерево добавляется ровно один ключ, если его раньше не было. Последующий splay сохраняет inorder-порядок, значит представляемое множество остаётся правильным.

Запрос

exists

Выполняется обычный BST-поиск:

  • при успехе поднимается найденная вершина;
  • при неуспехе поднимается последняя посещённая;
  • для пустого дерева поворот не вызывается.

Возвращаемое логическое значение определяется до перестройки и потому не меняется от поворотов.

Запрос

next

Требуется найти

\[ \min\{y\in S\mid y>x\}. \]

Во время спуска поддерживаются:

BaseNode* candidate;
BaseNode* last;

Инвариант

В начале каждой итерации правильный successor, если он существует, либо равен candidate, либо находится в текущем поддереве. При этом candidate пуст или его ключ строго больше \(x\).

Сохранение

  • Если текущий ключ больше \(x\), текущая вершина допустима и становится новым кандидатом. Её правое поддерево содержит ещё большие ключи и не может улучшить ответ, поэтому поиск продолжается слева.
  • Если текущий ключ не больше \(x\), сама вершина и всё её левое поддерево не подходят. Поиск продолжается справа.

Когда текущее поддерево становится пустым, единственным возможным ответом остаётся candidate.

После спуска выполняется SplayRotate(last). Указатель candidate остаётся валидным: повороты не удаляют вершины, поэтому после перестройки по нему можно вернуть ответ.

Запрос

prev

Операция симметрична next и ищет

\[ \max\{y\in S\mid y<x\}. \]
  • Если текущий ключ меньше \(x\), он становится кандидатом, а поиск продолжается справа.
  • Иначе текущая вершина и всё её правое поддерево не подходят, поэтому поиск продолжается слева.

После завершения также поднимается last, а кандидат используется только для ответа.

next и prev оставлены двумя отдельными функциями. Конкретная попытка вычислять обе границы одним однопутевым спуском некорректна при встрече ключа, равного \(x\): для successor нужно исследовать правое поддерево, а для predecessor — левое. Единую функцию построить возможно, но в случае равенства ей пришлось бы отдельно искать минимум справа и максимум слева; выбранные две симметричные реализации проще сохраняют нужные инварианты.

Порядковая статистика

Порядковая статистика kth

Пусть текущая вершина равна \(v\), а

\[ L=size[v_{\mathrm{left}}]. \]

Тогда:

  • если \(k=L\), вершина \(v\) имеет искомый ранг;
  • если \(k<L\), искомая вершина находится слева, и \(k\) не меняется;

  • если \(k>L\), искомая вершина находится справа, причём новый локальный ранг равен

    \[ k-L-1. \]

Единица соответствует самой вершине \(v\), которую также нужно пропустить.

Инвариант цикла

В начале каждой итерации k является нулевым рангом искомого элемента внутри текущего поддерева.

Переход влево не удаляет из рассмотрения меньшие элементы текущего поддерева, поэтому ранг сохраняется. При переходе вправо отбрасываются \(L\) вершин левого поддерева и сама текущая вершина, поэтому выполняется

k -= left_size + 1;

При допустимом исходном \(k\) процесс обязательно достигает единственной вершины с left_size == k. Она поднимается в корень.

Операция дерева

Удаление

Сначала FindNode(value) возвращает найденную либо последнюю посещённую вершину. Если дерево непусто, она поднимается в корень.

Если ключ не найден, операция на этом заканчивается. Если найден, удаляемая вершина \(v\) уже является корнем. Обозначим её левое и правое поддеревья через \(L\) и \(R\).

Из BST-инварианта:

\[ \forall a\in L,\ \forall b\in R: a<\operatorname{key}(v)<b. \]

Случай \(L=\varnothing\)

Новым корнем становится \(R\). Если \(R\ne\varnothing\), его родитель меняется на dummy_root_.

Случай \(L\ne\varnothing\)

  1. \(L\) временно становится отдельным деревом.
  2. В \(L\) находится максимальная вершина \(m\).
  3. Вершина \(m\) поднимается в корень \(L\).
  4. Поддерево \(R\) присоединяется как правый ребёнок \(m\).
  5. Размер \(m\) пересчитывается.

Поскольку \(m\) — максимум \(L\), после splay у него нет правого ребёнка. Кроме того,

\[ \forall a\in L\setminus\{m\}: a<m, \qquad \forall b\in R: m<b. \]

Следовательно, присоединение \(R\) справа сохраняет BST-инвариант. Удаляется ровно вершина с требуемым ключом.

Доказательство

Доказательство корректности всей структуры

Лемма 1. Один поворот сохраняет множество ключей и BST-инвариант

Поворот изменяет только связи между \(v\), \(p\) и промежуточным поддеревом \(B\). Ни одна вершина не создаётся и не удаляется. В правом повороте порядок

\[ A<v<B<p<C \]

до и после перестройки совпадает. Левый поворот симметричен. Поэтому inorder-последовательность и множество ключей сохраняются.

Лемма 2. Один поворот восстанавливает структурные инварианты

Новый корень локального поддерева присоединяется к прежнему родителю с правильной стороны. Для каждого изменённого ребра обновляются оба направления child и parent.

Состав поддеревьев изменяется только у \(p\) и \(v\), поэтому пересчётов UpdateSize(p) и затем UpdateSize(v) достаточно для восстановления инварианта размеров.

Лемма 3. SplayRotate(v) поднимает \(v\) в корень

Каждая итерация уменьшает глубину \(v\) на один или два. Все выполняемые повороты корректны по леммам 1 и 2. Поэтому цикл завершается, \(v\) становится ребёнком dummy_root_, а все инварианты сохраняются.

Лемма 4. Поисковые операции возвращают правильные ответы

exists следует единственному BST-пути к ключу. Инварианты кандидатов для next и prev показывают, что отбрасываются только поддеревья, в которых правильный ответ отсутствует либо не может улучшить кандидата. Инвариант локального ранга доказывает корректность kth.

Последующий splay не меняет inorder-порядок, поэтому уже определённые ответы остаются правильными.

Лемма 5. Модифицирующие операции представляют правильное множество

insert добавляет ровно отсутствующий ключ в единственное допустимое пустое место BST. delete сначала изолирует удаляемую вершину в корне, затем корректно объединяет диапазоны ключей \(L\) и \(R\). Повороты не меняют множество.

Теорема

После любой последовательности команд дерево содержит в точности текущее множество \(S\), сохраняет BST-, parent- и size-инварианты, а все запросы возвращают требуемые ответы.

Это следует из лемм 1–5 индукцией по числу обработанных команд.

Оценка ресурсов

Амортизированная сложность

Высота splay tree не ограничена логарифмом, поэтому худшее время одной операции:

\[ O(n). \]

Для амортизированного анализа каждой вершине сопоставляется ранг

\[ r(v)=\log size[v], \]

а потенциал дерева определяется как

\[ \Phi(T)=\sum_{v\in T} r(v). \]

Стандартная access lemma для splay tree утверждает: фактическая стоимость доступа и подъёма вершины \(x\), сложенная с изменением потенциала, не превосходит

\[ 1+3\bigl(r(\text{root})-r(x)\bigr)=O(\log n). \]

С точностью до постоянного множителя сюда входят и посещённые вершины поискового пути: число таких вершин отличается от числа последующих поворотов не более чем на константу. Для zig-zig и zig-zag оценка получается локальным подсчётом двух поворотов через изменение рангов затронутых вершин; затем оценки телескопируются вдоль пути к корню.

Каждая команда выполняет постоянное число BST-спусков и splay:

  • exists, next, prev, kth, insert — один доступ;
  • delete — доступ к удаляемому ключу и, при необходимости, доступ к максимуму левого поддерева.

Следовательно, при \(n\) текущих вершинах амортизированное время одной команды:

\[ O(\log(n+1)). \]

Для \(q\) команд, начиная с пустого дерева:

\[ T(q)=O(q\log(q+1)) \]

в амортизированном смысле.

Дерево хранит одну вершину на каждый ключ:

\[ M(n)=O(n). \]

Реализация операций итеративна, поэтому не использует линейную память рекурсивного стека даже при временно вырожденном дереве.

Post-Accepted

Accepted implementation

Ниже зафиксирована финальная структура решения из post-Accepted разбора. Обработчик команд читает пары command value до EOF. Заголовок <utility> подключён явно для std::pair.

#include <iostream>
#include <string>
#include <utility>

class Splay {
  struct BaseNode {
    int size{0};
    BaseNode* parent{this};
    BaseNode* left_child{nullptr};
    BaseNode* right_child{nullptr};

    BaseNode() = default;
    BaseNode(int size) : size(size) {}
    virtual ~BaseNode() = default;
  };

  struct Node : BaseNode {
    Node(int value) : BaseNode(1), value(value) {}

    int value;
  };

  static int Value(BaseNode* v) { return static_cast<Node*>(v)->value; }

  static int Size(BaseNode* v) {
    if (v == nullptr) {
      return 0;
    }
    return v->size;
  }

 public:
  void Insert(int value) {
    BaseNode* current = dummy_root_.left_child;
    BaseNode* parent = &dummy_root_;
    bool was_left = true;

    while (current != nullptr) {
      if (Value(current) == value) {
        SplayRotate(current);
        return;
      }

      parent = current;
      if (Value(current) < value) {
        was_left = false;
        current = current->right_child;
      } else {
        was_left = true;
        current = current->left_child;
      }
    }

    BaseNode* new_node = new Node(value);
    new_node->parent = parent;
    if (was_left) {
      parent->left_child = new_node;
    } else {
      parent->right_child = new_node;
    }
    SplayRotate(new_node);
  }

  // 0-indexed k.
  std::string Kth(int k) {
    BaseNode* current = dummy_root_.left_child;

    if (current == nullptr || k < 0 || k >= current->size) {
      return "none";
    }

    while (current != nullptr) {
      int left_size = Size(current->left_child);

      if (left_size == k) {
        SplayRotate(current);
        return std::to_string(Value(current));
      }

      if (k < left_size) {
        current = current->left_child;
      } else {
        k -= left_size + 1;
        current = current->right_child;
      }
    }

    return "none";
  }

  std::string Next(int value) {
    BaseNode* current = dummy_root_.left_child;
    BaseNode* candidate = nullptr;
    BaseNode* last = current;

    while (current != nullptr) {
      last = current;
      if (Value(current) > value) {
        candidate = current;
        current = current->left_child;
      } else {
        current = current->right_child;
      }
    }

    if (last != nullptr) {
      SplayRotate(last);
    }

    if (candidate == nullptr) {
      return "none";
    }
    return std::to_string(Value(candidate));
  }

  std::string Prev(int value) {
    BaseNode* current = dummy_root_.left_child;
    BaseNode* candidate = nullptr;
    BaseNode* last = current;

    while (current != nullptr) {
      last = current;
      if (Value(current) < value) {
        candidate = current;
        current = current->right_child;
      } else {
        current = current->left_child;
      }
    }

    if (last != nullptr) {
      SplayRotate(last);
    }

    if (candidate == nullptr) {
      return "none";
    }
    return std::to_string(Value(candidate));
  }

  void Delete(int value) {
    auto [v, was_found] = FindNode(value);
    if (v == nullptr) {
      return;
    }

    SplayRotate(v);

    if (!was_found) {
      return;
    }

    BaseNode* left_subtree = v->left_child;
    BaseNode* right_subtree = v->right_child;

    if (left_subtree == nullptr) {
      dummy_root_.left_child = right_subtree;
      if (right_subtree != nullptr) {
        right_subtree->parent = &dummy_root_;
      }
      delete v;
      return;
    }

    BaseNode* max_left_subtree = MaximumNode(left_subtree);
    left_subtree->parent = &dummy_root_;
    dummy_root_.left_child = left_subtree;
    SplayRotate(max_left_subtree);

    max_left_subtree->right_child = right_subtree;
    if (right_subtree != nullptr) {
      right_subtree->parent = max_left_subtree;
    }

    UpdateSize(max_left_subtree);
    delete v;
  }

  bool Find(int value) {
    auto [v, was_found] = FindNode(value);
    if (v != nullptr) {
      SplayRotate(v);
    }
    return was_found;
  }

 private:
  BaseNode dummy_root_;

  static void UpdateSize(BaseNode* v) {
    v->size = 1 + Size(v->left_child) + Size(v->right_child);
  }

  static void RotateLeft(BaseNode* v) {
    BaseNode* p = v->parent;
    BaseNode* b = v->left_child;

    v->left_child = p;
    p->parent = v;
    p->right_child = b;
    if (b != nullptr) {
      b->parent = p;
    }
  }

  static void RotateRight(BaseNode* v) {
    BaseNode* p = v->parent;
    BaseNode* b = v->right_child;

    v->right_child = p;
    p->parent = v;
    p->left_child = b;
    if (b != nullptr) {
      b->parent = p;
    }
  }

  static void Rotate(BaseNode* v) {
    BaseNode* p = v->parent;
    BaseNode* old_parent = p->parent;
    bool was_left = (old_parent->left_child == p);

    if (p->left_child == v) {
      RotateRight(v);
    } else if (p->right_child == v) {
      RotateLeft(v);
    }

    v->parent = old_parent;
    if (was_left) {
      old_parent->left_child = v;
    } else {
      old_parent->right_child = v;
    }

    UpdateSize(p);
    UpdateSize(v);
  }

  void SplayRotate(BaseNode* v) {
    while (v->parent != &dummy_root_) {
      BaseNode* p = v->parent;
      BaseNode* g = p->parent;
      bool is_zig_zig =
          (g->left_child == p && p->left_child == v) ||
          (g->right_child == p && p->right_child == v);

      if (g == &dummy_root_) {
        Rotate(v);
      } else if (is_zig_zig) {
        Rotate(p);
        Rotate(v);
      } else {
        Rotate(v);
        Rotate(v);
      }
    }
  }

  static BaseNode* MaximumNode(BaseNode* v) {
    while (v->right_child != nullptr) {
      v = v->right_child;
    }
    return v;
  }

  std::pair<BaseNode*, bool> FindNode(int value) const {
    BaseNode* current = dummy_root_.left_child;
    BaseNode* last = nullptr;

    while (current != nullptr) {
      last = current;
      if (Value(current) == value) {
        return {current, true};
      }

      if (Value(current) < value) {
        current = current->right_child;
      } else {
        current = current->left_child;
      }
    }

    return {last, false};
  }
};

int main() {
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);

  Splay tree;
  std::string command;
  int value;

  while (std::cin >> command >> value) {
    if (command == "insert") {
      tree.Insert(value);
    } else if (command == "delete") {
      tree.Delete(value);
    } else if (command == "exists") {
      std::cout << (tree.Find(value) ? "true" : "false") << '\n';
    } else if (command == "next") {
      std::cout << tree.Next(value) << '\n';
    } else if (command == "prev") {
      std::cout << tree.Prev(value) << '\n';
    } else if (command == "kth") {
      std::cout << tree.Kth(value) << '\n';
    }
  }
}

История поиска

Главный тупик

Основная трудность была не в BST-поиске, а в одновременном сохранении трёх связанных свойств во время поворотов:

  1. правильного направления дочерних связей;
  2. согласованности parent с left_child и right_child;
  3. корректного size после перестройки.

Одна неверная связь могла создать цикл, потерять поддерево или сделать порядковые статистики неправильными, хотя обычный поиск ещё мог работать на части тестов.

Отдельный концептуальный тупик возник в next и prev: первоначально поднимался кандидат ответа. Для правильного значения этого достаточно, но для амортизированной гарантии нужно перестраивать фактически пройденный путь, то есть поднимать последнюю посещённую вершину.

Разбор ошибок

Зафиксированные ошибки и исправления

  1. CORRECTION: перед локальным поворотом нужно сохранить прежнего дедушку old_parent; после изменения p->parent восстановить его уже нельзя.
  2. CORRECTION: если \(v\) — левый ребёнок \(p\), нужен правый поворот; если правый — левый.
  3. CORRECTION: новый корень локального поддерева нужно присоединить к old_parent с той же стороны, где раньше находился \(p\).
  4. CORRECTION: в zig-zig порядок равен Rotate(p) → Rotate(v), а не наоборот.
  5. CORRECTION: SplayRotate должен выполнять цикл до настоящего корня, а не только один zig или одну пару поворотов.
  6. CORRECTION: p в splay-шаге равен v->parent, а не v.
  7. CORRECTION: при пустом дереве нельзя разыменовывать current или вызывать SplayRotate(nullptr).
  8. CORRECTION: новый первый узел присоединяется к dummy_root_, поэтому начальный parent при вставке равен &dummy_root_.
  9. CORRECTION: допустимые нулевые ранги удовлетворяют \(0\le k<size[root]\); проверка должна использовать k >= size.
  10. CORRECTION: при переходе в правое поддерево в kth нужно вычесть left_size + 1, поскольку пропускается и текущая вершина.
  11. CORRECTION: при удалении левое или правое поддерево может быть пустым; присваивать его parent можно только после проверки на nullptr.
  12. ADDITION: после присоединения правого поддерева к максимуму левого требуется UpdateSize.
  13. CORRECTION: неуспешный delete также поднимает последнюю посещённую вершину.
  14. AMORTIZATION FIX: в next и prev поднимается last, а не candidate.
  15. DESIGN DECISION: единая функция, одновременно вычисляющая next и prev одним однопутевым спуском, отклонена: при равенстве ключей необходимые пути расходятся.
  16. PORTABILITY: для std::pair явно подключён <utility>; не следует полагаться на транзитивные включения других стандартных заголовков.
  17. ENGINEERING NOTE: у приведённого contest-класса нет деструктора, освобождающего оставшиеся вершины. На вывод программы это не влияет, а объём живого дерева всё равно равен \(O(n)\), но для повторно используемого контейнера нужны Clear()/деструктор и явно определённая политика копирования и перемещения.

Перенос идеи

Признаки похожих задач

Splay tree стоит рассматривать, когда:

  • требуется собственная реализация изменяемого ordered set;
  • нужны find, insert, erase, successor и predecessor;
  • запросы должны обрабатываться online;
  • допустима амортизированная, но не обязательно худшая логарифмическая стоимость одной операции;
  • последовательность запросов может обладать locality: недавно использованные ключи полезно держать близко к корню;
  • к BST нужно добавить агрегат поддерева — размер, сумму, минимум и т. п.;
  • нужны операции split/join либо порядковые статистики;
  • после неуспешного поиска важно перестроить путь к последней посещённой вершине.

Если требуется гарантированное \(O(\log n)\) в худшем случае на каждую операцию, лучше рассматривать AVL tree или red-black tree. Если допустима ожидаемая оценка и нужны особенно простые split/merge, часто удобнее treap.
