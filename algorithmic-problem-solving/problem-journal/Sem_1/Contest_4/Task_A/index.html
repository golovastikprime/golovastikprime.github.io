Семестр 1 · Контест 4

Задача A — AVL-дерево: insert и lower_bound

Accepted · C++ · 23 июля 2026

Обе требуемые операции естественно поддерживает binary search tree.

Условие

Условие

Нужно поддерживать множество целых чисел \(S\), изначально пустое, и обрабатывать запросы двух типов:

  • + x — добавить \(x\) в множество; повторная вставка уже существующего значения игнорируется;
  • ? x — найти минимальное значение \(y\in S\), для которого \(y\ge x\). Если такого значения нет, вывести -1.

Если операция + x идёт сразу после операции ?, ответом на которую было \(y\), в дерево передаётся значение

\[ (x+y)\bmod 10^9. \]

Эта зависимость от предыдущего ответа означает, что фактические ключи вставок появляются в ходе обработки запросов. Поэтому обычное предварительное coordinate compression по исходным аргументам операций + здесь неприменимо.

Подход

Ключевое наблюдение

Обе требуемые операции естественно поддерживает binary search tree:

  • BST-вставка находит единственное место нового ключа;
  • lower_bound(x) во время одного спуска отбрасывает поддеревья, в которых ответ заведомо отсутствует или не может быть лучше уже найденного кандидата.

Однако стоимость обеих операций равна \(O(h)\), где \(h\) — высота дерева. Обычное BST при монотонных вставках может превратиться в цепочку высоты \(\Theta(n)\). AVL-дерево после каждой вставки восстанавливает условие

\[ \left|h(v_{\mathrm{left}})-h(v_{\mathrm{right}})\right|\le 1, \]

поэтому его высота остаётся \(O(\log n)\), а каждая операция выполняется за \(O(\log n)\) в худшем случае.

Структура данных

Хранимая информация

Для каждой настоящей вершины хранятся:

int height;
BaseNode* parent;
BaseNode* left_child;
BaseNode* right_child;
int value;

Поле value находится в производной структуре Node, остальные поля — в BaseNode.

Дополнительно используется фиктивная вершина dummy_root_:

dummy_root_.left_child

всегда указывает на настоящий корень, а у настоящего корня

root->parent == &dummy_root_;

Благодаря этому корень всего дерева после поворота присоединяется тем же кодом, что и корень любого внутреннего поддерева.

Инварианты

Инварианты AVL-дерева

После завершения каждой операции поддерживаются четыре свойства.

1. BST-инвариант

Для каждой настоящей вершины \(v\):

  • каждый ключ в левом поддереве строго меньше Value(v);
  • каждый ключ в правом поддереве строго больше Value(v).

Равные ключи не вставляются, поэтому структура представляет множество, а не мультимножество.

2. Инвариант родительских указателей

Для каждого ребра \(v\to u\), направленного от родителя к ребёнку,

u->parent == v;

Родителем настоящего корня служит &dummy_root_.

3. Инвариант высот

Полагаем

\[ h(\varnothing)=0. \]

Для каждой настоящей вершины \(v\)

\[ h(v)=1+\max\bigl(h(v_{\mathrm{left}}),h(v_{\mathrm{right}})\bigr). \]

В частности, лист имеет высоту \(1\).

4. AVL-инвариант

Определим balance factor:

\[ bf(v)=h(v_{\mathrm{left}})-h(v_{\mathrm{right}}). \]

Для каждой вершины должно выполняться

\[ bf(v)\in\{-1,0,1\}. \]

Положительный balance factor означает перевес влево, отрицательный — вправо.
