Семестр 1 · Контест 4

Задача A — AVL-дерево: insert и lower_bound

Accepted · C++ · 23 июля 2026

Обе требуемые операции естественно поддерживает binary search tree.

Условие

Условие

Нужно поддерживать множество целых чисел \(S\), изначально пустое, и обрабатывать запросы двух типов:

  • + x — добавить \(x\) в множество; повторная вставка уже существующего значения игнорируется;
  • ? x — найти минимальное значение \(y\in S\), для которого \(y\ge x\). Если такого значения нет, вывести -1.

Если операция + x идёт сразу после операции ?, ответом на которую было \(y\), в дерево передаётся значение

\[ (x+y)\bmod 10^9. \]

Эта зависимость от предыдущего ответа означает, что фактические ключи вставок появляются в ходе обработки запросов. Поэтому обычное предварительное coordinate compression по исходным аргументам операций + здесь неприменимо.

Подход

Ключевое наблюдение

Обе требуемые операции естественно поддерживает binary search tree:

  • BST-вставка находит единственное место нового ключа;
  • lower_bound(x) во время одного спуска отбрасывает поддеревья, в которых ответ заведомо отсутствует или не может быть лучше уже найденного кандидата.

Однако стоимость обеих операций равна \(O(h)\), где \(h\) — высота дерева. Обычное BST при монотонных вставках может превратиться в цепочку высоты \(\Theta(n)\). AVL-дерево после каждой вставки восстанавливает условие

\[ \left|h(v_{\mathrm{left}})-h(v_{\mathrm{right}})\right|\le 1, \]

поэтому его высота остаётся \(O(\log n)\), а каждая операция выполняется за \(O(\log n)\) в худшем случае.

Структура данных

Хранимая информация

Для каждой настоящей вершины хранятся:

int height;
BaseNode* parent;
BaseNode* left_child;
BaseNode* right_child;
int value;

Поле value находится в производной структуре Node, остальные поля — в BaseNode.

Дополнительно используется фиктивная вершина dummy_root_:

dummy_root_.left_child

всегда указывает на настоящий корень, а у настоящего корня

root->parent == &dummy_root_;

Благодаря этому корень всего дерева после поворота присоединяется тем же кодом, что и корень любого внутреннего поддерева.

Инварианты

Инварианты AVL-дерева

После завершения каждой операции поддерживаются четыре свойства.

1. BST-инвариант

Для каждой настоящей вершины \(v\):

  • каждый ключ в левом поддереве строго меньше Value(v);
  • каждый ключ в правом поддереве строго больше Value(v).

Равные ключи не вставляются, поэтому структура представляет множество, а не мультимножество.

2. Инвариант родительских указателей

Для каждого ребра \(v\to u\), направленного от родителя к ребёнку,

u->parent == v;

Родителем настоящего корня служит &dummy_root_.

3. Инвариант высот

Полагаем

\[ h(\varnothing)=0. \]

Для каждой настоящей вершины \(v\)

\[ h(v)=1+\max\bigl(h(v_{\mathrm{left}}),h(v_{\mathrm{right}})\bigr). \]

В частности, лист имеет высоту \(1\).

4. AVL-инвариант

Определим balance factor:

\[ bf(v)=h(v_{\mathrm{left}})-h(v_{\mathrm{right}}). \]

Для каждой вершины должно выполняться

\[ bf(v)\in\{-1,0,1\}. \]

Положительный balance factor означает перевес влево, отрицательный — вправо.

Операция дерева

Вставка

Спуск как в обычном BST

Из корня выполняется спуск:

  • если новый ключ меньше текущего, переходим влево;
  • если больше — вправо;
  • если ключи равны, завершаем операцию без вставки.

Во время спуска сохраняются будущий родитель и сторона присоединения:

BaseNode* parent;
bool was_left;

was_left нужно определить сравнением ключей до перехода к ребёнку. Вычислять сторону после перехода выражением

parent->left_child == node

нельзя: если node == nullptr и оба ребёнка parent пусты, сравнение ошибочно сообщит, что был выбран левый ребёнок.

В найденное пустое место добавляется лист высоты \(1\) с корректным указателем parent.

Подъём и локальный инвариант Rebalance

Измениться могут только вершины на пути от родителя нового листа к корню. Перед вызовом Rebalance(v) выполняется следующий локальный инвариант:

  1. оба дочерних поддерева \(v\) уже являются корректными AVL-деревьями;
  2. их сохранённые высоты верны;
  3. BST-порядок и родительские связи внутри них корректны;
  4. нарушиться могли только высота и баланс самой вершины \(v\).

Rebalance(v) пересчитывает высоту \(v\), при необходимости выполняет одинарный или двойной поворот и возвращает новый корень того же множества ключей. Затем вызывающий код присоединяет возвращённую вершину к прежнему родителю \(v\).

После этого всё обработанное поддерево снова удовлетворяет четырём инвариантам. Следующей потенциально некорректной вершиной остаётся только его родитель, поэтому подъём можно продолжить.

Балансировка

Повороты

Поворот должен одновременно сохранить:

  1. inorder-порядок ключей;
  2. все поддеревья;
  3. двустороннюю согласованность child/parent;
  4. правильные высоты изменившихся вершин.

Правый поворот

Пусть старый корень поддерева — \(y\), его левый ребёнок — \(x\), а \(P\) — прежний родитель \(y\).

До поворота:

          P
          |
          y
         / \
        x   C
       / \
      A   B

После поворота:

          P
          |
          x
         / \
        A   y
           / \
          B   C

Из BST-инварианта до поворота

\[ A \lt x \lt B \lt y \lt C, \]

поэтому после перестановки тот же inorder-порядок сохраняется.

Необходимые изменения указателей:

y->left_child = b;
if (b != nullptr) {
  b->parent = y;
}

x->right_child = y;
y->parent = x;
x->parent = old_parent;

После возврата x вызывающий код устанавливает соответствующий указатель ребёнка у \(P\) равным x. Поддерево \(B\) обязательно переносится: без этого оно было бы потеряно.

Высоты пересчитываются снизу вверх:

UpdateHeight(y);
UpdateHeight(x);

Сначала меняются данные \(y\), затем \(x\), чья новая высота зависит от уже обновлённой высоты \(y\).

Левый поворот

Левый поворот симметричен. Для структуры

      x
     / \
    A   y
       / \
      B   C

получаем

        y
       / \
      x   C
     / \
    A   B

Поддерево \(B\) становится правым ребёнком \(x\); его parent меняется на \(x\). Старый корень \(x\) становится левым ребёнком \(y\), а новый корень \(y\) получает прежнего родителя \(x\). Высоты обновляются в порядке x, затем y.

Выбор поворота

Четыре случая нарушения баланса

После одной вставки у рассматриваемой вершины возможны только значения

\[ bf(v)\in\{-2,-1,0,1,2\}. \]

Выбор поворота определяется направлением перевеса вершины и её тяжёлого ребёнка.

Случай Условие Восстановление Минимальная вставка
LL \(bf(v)=2\), \(bf(v_{\mathrm{left}})\ge 0\) RotateRight(v) 3, 2, 1
RR \(bf(v)=-2\), \(bf(v_{\mathrm{right}})\le 0\) RotateLeft(v) 1, 2, 3
LR \(bf(v)=2\), \(bf(v_{\mathrm{left}})\lt 0\) левый поворот ребёнка, затем правый поворот \(v\) 3, 1, 2
RL \(bf(v)=-2\), \(bf(v_{\mathrm{right}})\gt 0\) правый поворот ребёнка, затем левый поворот \(v\) 1, 3, 2

Для двойного LR-поворота промежуточный корень сначала нужно вернуть на место:

v->left_child = RotateLeft(v->left_child);
return RotateRight(v);

RL-случай симметричен.

Доказательство

Почему повороты восстанавливают AVL-инвариант

Одинарный LL-поворот

Используем обозначения правого поворота выше и положим \(h(C)=t\). Из \(bf(y)=2\) следует

\[ h(x)=t+2. \]

Так как \(x\) до поворота сбалансирована и \(bf(x)\ge 0\),

\[ h(A)=t+1, \qquad h(B)\in\{t,t+1\}. \]

После поворота у \(y\) дети \(B,C\), высоты которых отличаются не более чем на единицу. Поэтому \(y\) сбалансирована.

  • Если \(h(B)=t\), то новая высота \(y\) равна \(t+1\), как и высота \(A\).
  • Если \(h(B)=t+1\), то новая высота \(y\) равна \(t+2\), то есть на единицу больше высоты \(A\).

Следовательно, новый корень \(x\) также сбалансирован. RR-случай доказывается симметрично.

Двойной LR-поворот

Пусть структура имеет вид

          y
         / \
        x   D
       / \
      A   z
         / \
        B   C

Здесь \(bf(y)=2\), а \(bf(x)\lt 0\). Поскольку \(x\) сама является AVL-вершиной, фактически \(bf(x)=-1\).

Положим \(h(D)=t\). Тогда

\[ h(x)=t+2, \qquad h(z)=t+1, \qquad h(A)=t. \]

Из сбалансированности \(z\) следует

\[ h(B),h(C)\in\{t-1,t\}. \]

После левого поворота вокруг \(x\) и правого вокруг \(y\) получается

          z
         / \
        x   y
       / \ / \
      A  B C  D

У \(x\) оба ребёнка имеют высоту не больше \(t\), причём \(h(A)=t\); поэтому новая высота \(x\) равна \(t+1\), и \(x\) сбалансирована. Симметрично новая высота \(y\) равна \(t+1\), и \(y\) сбалансирована. Дети нового корня \(z\) имеют одинаковую высоту \(t+1\), значит \(bf(z)=0\).

RL-случай доказывается зеркально.

Таким образом, каждый выбранный поворот сохраняет BST-порядок и восстанавливает AVL-инвариант во всём рассматриваемом поддереве.

Корректность запроса

Корректность lower_bound

Нужно найти

\[ \min\{k\in S\mid k\ge x\}. \]

Во время спуска хранятся текущая вершина v и указатель candidate.

Инвариант цикла

В начале каждой итерации правильный ответ, если он существует, находится либо в текущем поддереве v, либо равен candidate; при этом candidate == nullptr или ключ кандидата не меньше \(x\).

Изначально текущим является всё дерево, а candidate == nullptr, поэтому инвариант выполнен.

Сохранение

  • Если Value(v) >= x, вершина \(v\) допустима. Она становится новым кандидатом. Всё правое поддерево содержит ключи больше Value(v) и потому не может дать меньший ответ; продолжаем поиск слева.
  • Если Value(v) < x, сама вершина и всё её левое поддерево содержат слишком маленькие ключи; продолжаем поиск справа, не меняя кандидата.

В обоих случаях отбрасываются только вершины, которые не могут быть правильным ответом, поэтому инвариант сохраняется.

Завершение

Когда v == nullptr, текущее поддерево пусто. По инварианту единственным возможным ответом остаётся candidate.

  • Если кандидат существует, его ключ является минимальным ключом, не меньшим \(x\).
  • Если candidate == nullptr, подходящего ключа в дереве нет и возвращается -1.

Доказательство

Доказательство корректности всей структуры

Лемма 1. Insert сохраняет представляемое множество и BST-инвариант

Спуск сравнивает новый ключ с текущими ключами. При равенстве структура не меняется. Иначе новый лист присоединяется в первое пустое место на единственном пути поиска, поэтому все ключи слева от каждой вершины остаются меньше неё, а справа — больше. В дерево добавляется ровно требуемый новый ключ.

Повороты не меняют inorder-последовательность, следовательно, последующая балансировка также сохраняет множество ключей и BST-инвариант.

Лемма 2. Insert восстанавливает структурные инварианты

Перед обработкой очередной вершины её дети уже являются корректными AVL-поддеревьями. Rebalance выбирает один из исчерпывающих случаев по двум balance factor. По доказательству выше выбранный поворот восстанавливает баланс и пересчитывает высоты снизу вверх.

Каждое изменённое ребро получает согласованный обратный parent, а возвращённый корень поддерева присоединяется к прежнему родителю. Поэтому после подъёма до dummy_root_ высоты, баланс и родительские указатели корректны во всём дереве.

Лемма 3. LowerBound возвращает требуемый ключ

Это непосредственно следует из доказанного инварианта его цикла.

Теорема

После любого префикса запросов AVL-дерево содержит ровно все различные фактически вставленные значения. Каждый запрос ? x возвращает минимальное из них, не меньшее \(x\), либо -1, если такого значения нет. Значит, вся последовательность запросов обрабатывается корректно.

Оценка высоты

Почему высота логарифмическая

Пусть \(N(h)\) — минимальное число вершин в AVL-дереве высоты \(h\). Чтобы получить высоту \(h\) при разности высот детей не более единицы, минимальные высоты детей должны быть \(h-1\) и \(h-2\). Поэтому

\[ N(0)=0, \qquad N(1)=1, \qquad N(h)=1+N(h-1)+N(h-2). \]

Отсюда

\[ N(h)\ge F_{h+2}-1, \]

где \(F_k\) — числа Фибоначчи. Поскольку \(F_k\) растут экспоненциально, из \(n\ge N(h)\) следует

\[ h=O(\log(n+1)). \]

Оценка ресурсов

Сложность

Пусть в дереве находится \(n\) различных ключей.

  • Insert выполняет один спуск и один подъём, затрачивая \(O(1)\) работы в каждой посещённой вершине:
    \[ O(\log(n+1)). \]
  • LowerBound выполняет один спуск:
    \[ O(\log(n+1)). \]
  • дерево хранит одну вершину на каждый различный ключ:
    \[ O(n) \]
    памяти.

Для \(q\) запросов в худшем случае

\[ T(q)=O(q\log(q+1)), \qquad M(q)=O(q). \]

Рекурсивный Clear использует \(O(\log(n+1))\) дополнительной памяти стека, потому что глубина рекурсии равна высоте AVL-дерева.

История поиска

Failure modes реализации

В исходном post-Accepted разборе не выделен единственный главный тупик; зафиксировано несколько связанных ошибок указателей и инвариантов.

Несогласованное присоединение после поворота

Поворот меняет корень поддерева. Если изменить только локальные left_child и right_child, но не вернуть новый корень и не присоединить его к прежнему родителю, часть дерева станет недостижимой или родительские связи разойдутся.

Безопасная схема:

  1. поворот возвращает новый корень поддерева;
  2. вызывающий код заменяет соответствующего ребёнка прежнего родителя;
  3. для каждого перенесённого ребёнка обновляется parent;
  4. высоты пересчитываются снизу вверх.

Другие зафиксированные ошибки

  • сторона вставки определялась после перехода в nullptr;
  • при повороте могло потеряться промежуточное поддерево \(B\);
  • знаки LR и RL путались относительно определения \(bf=h(left)-h(right)\);
  • вместо отдельного кандидата LowerBound использовался последний родитель;
  • высоты после поворота могли пересчитываться в неверном порядке;
  • удаление Node через BaseNode* требует виртуального деструктора базового класса.

Перенос идеи

Признаки похожих задач

AVL-дерево стоит рассматривать, когда:

  • запросы действительно зависят от предыдущих ответов и должны обрабатываться онлайн;
  • требуется поддерживать изменяемое упорядоченное множество;
  • нужны операции insert, find, lower_bound, upper_bound, predecessor или successor;
  • обычное BST может выродиться на специально подобранном порядке вставок;
  • требуется гарантированное, а не ожидаемое, \(O(\log n)\) на операцию;
  • готовый std::set использовать нельзя или задача требует собственной реализации дерева.

Близкие структуры:

  • red-black tree — более слабая балансировка, обычно с меньшим числом поворотов;
  • treap — более простые split/merge, но ожидаемая, а не детерминированная, логарифмическая высота;
  • std::set — готовое сбалансированное дерево, если собственная реализация не является частью задачи.
