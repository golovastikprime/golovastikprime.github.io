Задача A — объединение отрезков

Accepted · C++ · 23 июля 2026

Именно сортировка превращает глобальную задачу об объединении всех отрезков в локальное сравнение с одним объектом curr.

Условие

Условие

Даны \(n\) отрезков на числовой прямой:

\[ [l_1,r_1], [l_2,r_2],\ldots,[l_n,r_n], \qquad l_i\le r_i. \]

Нужно представить их объединение в виде минимального набора попарно не пересекающихся отрезков и вывести полученные отрезки в порядке слева направо.

Вход содержит число \(n\), а затем \(n\) пар границ \(l_i,r_i\). В выходе сначала печатается число компонент объединения, после чего — их границы.

В переданном решении координаты хранятся в long long.

Подход

Ключевое наблюдение

Если расположить отрезки по неубыванию левой границы, то очередной отрезок может взаимодействовать только с последней ещё не завершённой компонентой объединения.

Пусть эта компонента равна

\[ \texttt{curr}=[L,R], \]

а следующий отрезок после сортировки равен

\[ [l,r]. \]

Возможны ровно два случая.

Отрезки пересекаются или соприкасаются

Если

\[ l\le R, \]

то новый отрезок начинается не правее конца текущей компоненты. Их объединение снова является одним отрезком:

\[ [L,R]\cup[l,r]=[L,\max(R,r)]. \]

Левая граница не меняется, а правую необходимо заменить на максимум.

Между отрезками есть разрыв

Если

\[ l>R, \]

то текущую компоненту уже невозможно расширить. Действительно, у всех ещё не рассмотренных отрезков левая граница не меньше \(l\), а значит, строго больше \(R\).

Поэтому \([L,R]\) можно окончательно добавить в ответ, а новый отрезок сделать текущей компонентой.

Именно сортировка превращает глобальную задачу об объединении всех отрезков в локальное сравнение с одним объектом curr.

Сортировка

Почему достаточно сортировать только по левой границе

Решение сравнивает точки только по полю x, то есть по левой границе отрезка. Специальный порядок правых границ при равных левых границах не требуется.

Пусть несколько отрезков начинаются в одной точке \(l\). Какой бы из них ни обрабатывался первым, каждый следующий удовлетворяет

\[ l\le \texttt{curr.right}, \]

поскольку для корректного отрезка \(\texttt{curr.right}\ge l\). Следовательно, все такие отрезки попадут в одну компоненту, а её правая граница станет максимумом их правых границ.

Стабильность реализованного merge sort сохраняет исходный порядок при равных левых границах, но корректность алгоритма от этого свойства не зависит.

Алгоритм

Алгоритм

  1. Считать все отрезки.
  2. Отсортировать их по неубыванию левой границы.
  3. Сделать первый отрезок текущей компонентой curr.
  4. Последовательно рассматривать остальные отрезки:
    • если next.x <= curr.y, расширить правую границу: 
      curr.y = std::max(curr.y, next.y);
    • иначе добавить curr в ответ и присвоить curr = next.
  5. После цикла добавить последнюю компоненту curr.
  6. Вывести число компонент и сами компоненты.

Последнее добавление выполняется отдельно, поскольку внутри цикла компонента попадает в ответ только после обнаружения следующего разрыва.

Инвариант

Инвариант прохода

После обработки отсортированных отрезков

\[ a_0,a_1,\ldots,a_{i-1}, \]

но перед обработкой \(a_i\), выполняются следующие свойства:

  1. ans содержит все уже завершённые компоненты объединения обработанных отрезков, кроме самой правой компоненты;
  2. curr в точности равен самой правой компоненте объединения обработанных отрезков;
  3. отрезки в ans расположены слева направо и попарно разделены строгими промежутками;
  4. каждый отрезок из ans лежит строго левее curr;
  5. объединение отрезков из ans вместе с curr совпадает с объединением \(a_0,\ldots,a_{i-1}\).

База

Перед первой итерацией цикла обработан только \(a_0\):

\[ \texttt{curr}=a_0,\qquad \texttt{ans}=\varnothing. \]

Единственный обработанный отрезок является самой правой компонентой, поэтому все свойства инварианта выполнены.

Сохранение: \(a_i\) пересекает curr

Пусть \(a_i=[l_i,r_i]\) и \(l_i\le\texttt{curr.right}\).

Из сортировки следует

\[ l_i\ge\texttt{curr.left}. \]

Поэтому \(a_i\) пересекает текущую компоненту или соприкасается с ней, а их объединение равно

\[ [\texttt{curr.left}, \max(\texttt{curr.right},r_i)]. \]

Операция с std::max в точности вычисляет новую правую компоненту. Ранее завершённые компоненты не меняются, поэтому инвариант сохраняется.

Сохранение: перед \(a_i\) есть разрыв

Пусть \(l_i>\texttt{curr.right}\). Тогда \(a_i\) отделён от curr разрывом.

Кроме того, для каждого будущего \(a_j\), где \(j>i\), из сортировки следует

\[ l_j\ge l_i>\texttt{curr.right}. \]

Значит, ни текущий, ни какой-либо будущий отрезок уже не сможет соединиться с curr. Добавление curr в ans окончательно фиксирует очередную компоненту, а \(a_i\) становится новой самой правой компонентой. Инвариант снова сохраняется.

Доказательство

Доказательство корректности

Докажем, что алгоритм выводит в точности компоненты объединения всех входных отрезков.

По доказанному инварианту после завершения цикла:

  • ans содержит все завершённые компоненты объединения;
  • curr равен последней, самой правой компоненте;
  • вместе они образуют объединение всех \(n\) входных отрезков.

Алгоритм добавляет curr в ans, поэтому после этого объединение выведенных отрезков совпадает с объединением входных.

Остаётся доказать минимальность представления. Две соседние компоненты добавляются раздельно только в случае

\[ \texttt{next.left}>\texttt{curr.right}, \]

то есть между ними существует непустой промежуток, не принадлежащий ни одному из уже обработанных отрезков. По сортировке будущие отрезки также начинаются правее этого разрыва, поэтому заполнить его невозможно. Следовательно, такие компоненты нельзя объединить в один отрезок без добавления лишних точек.

Итак, алгоритм выводит точное объединение и использует минимально возможное число попарно разделённых отрезков.

Сортировка

Корректность merge sort

Функция MergeSort(array, l, r) сортирует включительный диапазон \([l,r]\).

  • При \(l\ge r\) диапазон содержит не более одного элемента и уже отсортирован.
  • Иначе диапазон разбивается на \([l,m]\) и \([m+1,r]\).
  • По индукции рекурсивные вызовы сортируют обе половины.
  • Merge каждый раз выбирает элемент с меньшей левой границей из начал двух отсортированных половин, а затем дописывает оставшийся хвост.

Следовательно, после Merge весь диапазон \([l,r]\) отсортирован по неубыванию x.

При равных x выбирается элемент из левой половины, поэтому реализация также является стабильной.

Оценка

Сложность

Пусть дано \(n\) отрезков, а в ответе получилось \(k\le n\) компонент.

Для merge sort:

\[ T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n). \]

Последующий проход и вывод занимают

\[ \Theta(n)+\Theta(k)=\Theta(n). \]

Итоговая временная сложность:

\[ \boxed{\Theta(n\log n)}. \]

Во время одного слияния временные массивы суммарно содержат столько элементов, сколько находится в текущем диапазоне. Пиковая дополнительная память merge sort равна \(O(n)\), глубина рекурсии — \(O(\log n)\), а массив ответа занимает \(O(k)\subseteq O(n)\).

Итоговая память:

\[ \boxed{O(n)}. \]

Проверка

Граничные случаи

  • Один отрезок: он сразу становится единственной компонентой ответа.
  • Все отрезки попарно разделены: в ответ попадут все \(n\) отрезков.
  • Все отрезки пересекаются: получится одна компонента.
  • Один отрезок вложен в другой: \([1,10]\), \([2,3]\); правая граница не должна уменьшиться.
  • Одинаковые отрезки: дубликаты не меняют объединение.
  • Равные левые границы: \([1,3]\), \([1,10]\); порядок между ними не влияет на результат.
  • Соприкосновение в одной точке: \([1,2]\), \([2,5]\); условие <= объединяет их в \([1,5]\).
  • Отрезок-точка: \([4,4]\); он корректно обрабатывается как вырожденный отрезок.
  • Отрицательные координаты: порядок и сравнения остаются теми же.

Failure modes

Почему нужны именно сортировка и max

Без сортировки

Для порядка

\[ [5,6],\ [1,10] \]

локальный проход начал бы curr с \([5,6]\). Простая проверка пересечения уже не смогла бы восстановить потерянную левую границу \(1\).

Сортировка гарантирует, что левая граница curr всегда является самой левой границей текущей компоненты.

Нельзя присваивать curr.y = next.y

На отрезках

\[ [1,10],\ [2,3] \]

такое присваивание ошибочно уменьшило бы компоненту до \([1,3]\). Правильное обновление обязано сохранять наиболее далёкую достигнутую правую границу:

\[ \texttt{curr.y}=\max(\texttt{curr.y},\texttt{next.y}). \]

Нельзя забывать последнюю компоненту

Компонента добавляется внутри цикла только при обнаружении следующего разрыва. После последнего входного отрезка такого события уже нет, поэтому финальный ans.push_back(curr) обязателен.

Реализация

Замечания к реализации

Отсутствует <algorithm>

Код использует std::max, но явно не подключает стандартный заголовок:

#include <algorithm>

Некоторые реализации стандартной библиотеки могут случайно предоставить объявление через транзитивные включения, однако стандарт C++ этого не гарантирует. Это portability defect, даже если конкретный компилятор принял программу.

Предусловие \(n\ge 1\)

Строка

Point curr = a[0];

требует непустого входного массива. Если условие гарантирует \(n\ge1\), всё корректно. Если \(n=0\) допустимо, перед обращением к a[0] нужен отдельный случай.

Предусловие \(l_i\le r_i\)

Доказательство использует стандартное представление отрезка, в котором левая граница не превосходит правую. Если вход не гарантирует этот порядок, каждую пару необходимо предварительно нормализовать:

\[ (l_i,r_i)\leftarrow (\min(l_i,r_i),\max(l_i,r_i)). \]

Семантика соприкасающихся отрезков

Условие next.x <= curr.y соответствует объединению замкнутых отрезков и выдаёт компоненты без разрывов. Если в другой задаче требуется считать соприкасающиеся объекты разными, сравнение должно быть строгим. Выбор <= или < всегда должен следовать из точного определения интервала и требуемого формата ответа.

Failure mode

Главный failure mode

Личный тупик до Accepted не был описан, поэтому он не приписывается автору. Главная логическая опасность этого решения — завершить curr раньше, чем доказано, что ни один будущий отрезок не сможет его расширить.

Такое доказательство появляется только после сортировки: как только очередная левая граница стала больше curr.y, все будущие левые границы также будут больше curr.y. Без монотонного порядка тот же локальный шаг некорректен.

Перенос идеи

Признаки похожих задач

Подход «sort + one pass» стоит проверять, когда:

  • объекты являются отрезками на одной прямой;
  • требуется найти объединение, число компонент или суммарную покрытую длину;
  • после упорядочивания по одной границе будущие объекты уже не могут вернуться в завершённую область;
  • для текущей группы достаточно хранить только левую границу и наиболее далёкую правую границу;
  • решение должно объединять цепочки пересечений, даже если первый и последний отрезки напрямую не пересекаются.

Например,

\[ [1,4],\ [3,7],\ [6,9] \]

образуют одну компоненту \([1,9]\): текущая правая граница последовательно расширяется с \(4\) до \(7\), а затем до \(9\).

Тот же шаблон используется для:

  • подсчёта суммарной длины объединения отрезков;
  • вставки нового отрезка в уже отсортированный набор;
  • поиска промежутков, не покрытых ни одним отрезком;
  • объединения временных окон;
  • группировки событий в пересекающиеся временные блоки.

Главный сигнал: после сортировки существует одна текущая компонента, и решение о её завершении становится необратимым.

Явно отмеченные содержательные изменения
