Семестр 1 · Контест 1

Задача B — \(k\)-я порядковая статистика

Reviewed · C++ · 23 июля 2026

Заявленная линейная гарантия отсутствует: допустимый вход с большим числом равных элементов приводит к квадратичному времени независимо от выбора pivot.

Условие

Условие

Даны числа

\[ n,\quad k,\quad A_0,\quad A_1, \]

где

\[ 1\le k\le n\le 10^7, \qquad 0\le A_0,A_1<10^7+4321. \]

Остальные элементы массива задаются рекуррентно:

\[ A_i= \bigl(123A_{i-1}+45A_{i-2}\bigr) \bmod (10^7+4321), \qquad i\ge 2. \]

Требуется вывести \(k\)-ю порядковую статистику массива, то есть элемент, который находился бы на позиции \(k\) после сортировки массива по неубыванию. В условии \(k\) нумеруется с единицы.

Для получения удвоенного балла алгоритм должен быть:

  • детерминированным;
  • работающим за \(O(n)\) в худшем случае.

Review

Статус переданного решения

Переданное решение реализует QuickSelect со случайно выбираемым pivot и двухчастным разбиением Lomuto.

Необходимо различать три утверждения.

  1. Идея выбора одной части после partition корректна.
  2. Реализация некорректна для \(n=1\): происходит запись за границу вектора в nums[1].
  3. Заявленная линейная гарантия отсутствует: для допустимого входа с большим числом равных элементов реализация работает за \(\Theta(n^2)\), независимо от выбора pivot.

Следовательно, по одному только коду нельзя записывать итоговую сложность как \(O(n)\), а бонусное требование текущий алгоритм не выполняет.

Подход

Ключевое наблюдение

Чтобы найти один элемент заданного ранга, необязательно полностью сортировать массив.

После разбиения относительно pivot можно получить позицию \(p\), для которой

\[ \begin{aligned} A_i&\le A_p &&\text{для } i<p,\\ A_i&>A_p &&\text{для } i>p. \end{aligned} \]

Тогда pivot уже стоит на допустимой позиции в отсортированном массиве:

  • если \(p=k\), ответ найден;
  • если \(k<p\), достаточно продолжить только в левой части;
  • если \(k>p\), достаточно продолжить только в правой части.

Вторая часть массива после каждого partition отбрасывается целиком. Именно это отличает selection от полной сортировки.

В программе входное \(k\) переводится из нумерации с единицы в нумерацию с нуля:

QuickSelect(nums, k - 1)

Это преобразование корректно.

Данные

Генерация массива

Обозначим

\[ M=10^7+4321. \]

Для каждого \(i\ge2\) программа вычисляет

\[ \begin{aligned} a&=(123A_{i-1})\bmod M,\\ b&=(45A_{i-2})\bmod M,\\ A_i&=(a+b)\bmod M. \end{aligned} \]

По свойствам остатка

\[ 0\le A_i<M, \]

поэтому все сгенерированные значения удовлетворяют тому же диапазону, что и начальные.

Использование 64-битного типа для умножений безопасно. При данных ограничениях даже сами произведения значительно меньше максимального значения std::int64_t.

Инвариант

Инвариант Partition

Рассматривается полуобработанный включительный диапазон

\[ [\texttt{left},\texttt{right}]. \]

Выбранный pivot временно переносится в nums[right]. Перед очередной итерацией цикла с индексом \(i\) выполняется инвариант:

  1. элементы диапазона
    \[ [\texttt{left},j) \]
    не превосходят pivot;
  2. элементы диапазона
    \[ [j,i) \]
    строго больше pivot;
  3. элементы диапазона
    \[ [i,\texttt{right}) \]
    ещё не классифицированы;
  4. сам pivot находится в nums[right].

База

В начале

\[ i=j=\texttt{left}. \]

Оба классифицированных диапазона пусты, поэтому инвариант выполнен.

Сохранение

Если

\[ \texttt{nums[i]}\le \texttt{pivot}, \]

элемент меняется местами с nums[j], после чего \(j\) увеличивается. Рассмотренный элемент добавляется к первой области, а находившийся на позиции \(j\) элемент переносится в область элементов, больших pivot.

Если

\[ \texttt{nums[i]}>\texttt{pivot}, \]

обмен не нужен: элемент сразу расширяет вторую область.

В обоих случаях после увеличения \(i\) инвариант сохраняется.

Завершение

После цикла имеем

\[ \begin{aligned} \texttt{nums[left..j)}&\le\texttt{pivot},\\ \texttt{nums[j..right)}&>\texttt{pivot}. \end{aligned} \]

Обмен nums[j] и nums[right] ставит pivot на позицию \(j\). Поэтому

\[ \begin{aligned} \texttt{nums[left..j)}&\le\texttt{nums[j]},\\ \texttt{nums(j..right]}&>\texttt{nums[j]}. \end{aligned} \]

Функция корректно возвращает \(p=j\).

Корректность

Корректность QuickSelect

Докажем по индукции по длине активного диапазона, что вызов

QuickSelectHelper(nums, left, right, k)

возвращает элемент требуемого ранга при условии

\[ \texttt{left}\le k\le\texttt{right}. \]

База

Если

\[ \texttt{left}=\texttt{right}, \]

в диапазоне остался один элемент. Он и является искомым.

Индукционный переход

Пусть Partition вернул позицию \(p\). По доказанному свойству разбиения все элементы слева от \(p\) не превосходят nums[p], а все элементы справа строго больше него. Следовательно, nums[p] может занимать позицию \(p\) в неубывающей сортировке активного диапазона.

Возможны три случая.

  • \(p=k\). Тогда nums[p] — искомая порядковая статистика.
  • \(p>k\). Искомый элемент находится в \([\texttt{left},p-1]\); правая часть не может содержать ранг \(k\).
  • \(p<k\). Искомый элемент находится в \([p+1,\texttt{right}]\); левая часть вместе с pivot занимает более ранние позиции.

В двух последних случаях рекурсивный вызов выполняется на строго меньшем диапазоне. По индукционному предположению он возвращает правильный ответ.

Таким образом, сама логика QuickSelect корректна.

Оценка

Почему текущая оценка не равна \(O(n)\)

Один вызов Partition на диапазоне длины \(m\) занимает

\[ \Theta(m). \]

Если pivot каждый раз отделяет только один элемент, возникает рекуррентность

\[ T(m)=T(m-1)+\Theta(m), \]

откуда

\[ T(n)=\Theta(n^2). \]

Случайный pivot обычно используется, чтобы получить ожидаемую оценку \(\Theta(n)\). Однако стандартный анализ предполагает подходящее случайное распределение pivot и корректную обработку равных ключей. Переданная реализация не удовлетворяет второму условию.

Контрпример

Контрпример из допустимого входа: все элементы равны

Возьмём

\[ A_0=A_1=0. \]

Тогда по индукции

\[ A_i=(123\cdot0+45\cdot0)\bmod M=0 \]

для каждого \(i\). Весь массив состоит из нулей.

При использовании условия

if (nums[i] <= pivot)

каждый элемент переносится в левую часть. Поэтому после partition

\[ p=\texttt{right} \]

при любом выбранном pivot.

Если, например, \(k=1\), то есть внутренний индекс равен нулю, размеры последовательных активных диапазонов равны

\[ n,\ n-1,\ n-2,\ \ldots,\ 1. \]

Суммарная работа:

\[ \Theta(n)+\Theta(n-1)+\cdots+\Theta(1) =\Theta(n^2). \]

Выбор pivot через rand() здесь вообще не помогает: все возможные pivot имеют одно и то же значение.

Кроме превышения времени, глубина рекурсии становится \(\Theta(n)\), что при \(n\le10^7\) практически неизбежно приводит к переполнению стека.

Дубликаты

Почему замена <= на < недостаточна

Если заменить сравнение на строгое, на массиве одинаковых элементов pivot будет каждый раз попадать в левую границу, а не в правую.

Это исправит конкретный случай \(k=1\), но создаст ту же цепочку для ранга, близкого к \(n\). Следовательно, проблема не в выборе одного из двух знаков, а в разбиении равных pivot элементов между рекурсивными частями.

Для устойчивой обработки дубликатов нужно трёхчастное разбиение:

\[ \underbrace{A_i<pivot}_{[L,M_1)} \quad \underbrace{A_i=pivot}_{[M_1,M_2)} \quad \underbrace{A_i>pivot}_{[M_2,R)}. \]

Если \(k\in[M_1,M_2)\), ответ сразу равен pivot. Рекурсия выполняется только для одной из строгих частей.

Трёхчастное разбиение устраняет квадратичное поведение на одинаковых элементах, но при случайном pivot всё ещё даёт лишь ожидаемую линейную оценку, а не детерминированную гарантию худшего случая.

Исправление

Как выполнить бонусное требование

Следующий раздел описывает исправление, а не алгоритм из переданного кода.

Для детерминированного \(O(n)\) выбора pivot можно использовать median of medians, или BFPRT.

Для активного диапазона длины \(m\):

  1. разбить элементы на группы по пять;
  2. найти медиану каждой группы;
  3. рекурсивно найти медиану массива этих медиан;
  4. использовать её как pivot;
  5. выполнить трёхчастное разбиение;
  6. продолжить только в той строгой части, где находится искомый ранг.

Почему остаётся не более \(7m/10+O(1)\) элементов

Не менее половины групповых медиан не меньше median of medians. В каждой полной группе, медиана которой не меньше pivot, существуют как минимум три элемента, не меньших pivot.

Симметрично, как минимум три элемента в каждой из не менее чем половины подходящих групп не превосходят pivot. С учётом неполной последней группы и группы самого pivot с каждой стороны гарантированно отбрасывается примерно \(3m/10\) элементов.

Поэтому рекурсивная часть после partition имеет размер не более

\[ \frac{7m}{10}+O(1). \]

Рекуррентность

Поиск median of medians выполняется на массиве размера примерно \(m/5\), а после partition остаётся не более \(7m/10+O(1)\) элементов:

\[ T(m) \le T\left(\left\lceil\frac m5\right\rceil\right) + T\left(\frac{7m}{10}+O(1)\right) + \Theta(m). \]

Так как

\[ \frac15+\frac7{10}=\frac9{10}<1, \]

получаем

\[ \boxed{T(m)=\Theta(m)}. \]

Выбор pivot полностью определяется входом, поэтому алгоритм детерминирован и даёт линейную оценку в худшем случае.

Альтернатива

Альтернатива, использующая ограниченный диапазон значений

В этой конкретной задаче все числа лежат в диапазоне

\[ [0,M),\qquad M=10^7+4321. \]

Поэтому можно не хранить сам массив, а поддерживать массив частот:

  1. сгенерировать очередное \(A_i\);
  2. увеличить frequency[A_i];
  3. пройти значения от \(0\) до \(M-1\), накапливая число элементов;
  4. первое значение, на котором накопленная частота стала не меньше \(k\), является ответом.

Сложность такого решения:

\[ \Theta(n+M) \]

по времени и

\[ \Theta(M) \]

по памяти.

Это детерминированное практическое решение для фиксированного модуля из условия, но оно не является общим алгоритмом selection. Если размер вселенной \(M\) считать отдельным входным параметром, оценка имеет вид \(O(n+M)\), а не \(O(n)\). Для общего требования deterministic linear selection нужен BFPRT.

Оценка

Сложность переданного решения

Генерация

Генерация массива требует

\[ \Theta(n) \]

времени.

Вектор из \(n\) элементов типа int64_t занимает

\[ 8n\text{ байт}. \]

При \(n=10^7\) это около \(80\,000\,000\) байт, или \(76.3\) MiB.

Selection

  • один Partition: \(\Theta(m)\) на активном диапазоне длины \(m\);
  • лучший случай: \(\Theta(n)\);
  • ожидаемый случай при дополнительных предположениях о pivot и ключах: \(\Theta(n)\);
  • худший случай текущей реализации:
    \[ \boxed{\Theta(n^2)}; \]
  • худшая глубина рекурсии:
    \[ \boxed{\Theta(n)}. \]

Итоговая память определяется входным вектором и стеком рекурсии:

\[ O(n)+O(\text{depth}). \]

В худшем случае обе величины линейны. Практически рекурсивный стек может исчерпаться значительно раньше, чем будет достигнута теоретическая граница \(n\).

Ошибка

Ошибка при \(n=1\)

Условие допускает

\[ n=1. \]

Но программа сначала создаёт вектор размера \(n\), а затем выполняет:

std::cin >> nums[0] >> nums[1];

При \(n=1\) элемента nums[1] не существует. Запись за границу вектора является undefined behavior.

Например, вход

1 1 7 9

допустим, а правильный ответ равен \(7\). Значение \(A_1\) всё равно присутствует во входе, но его нужно считать в отдельную переменную, не записывая в несуществующий элемент массива.

Корректная логика инициализации должна отдельно учитывать размеры:

  • \(A_0\) записывается, если \(n\ge1\);
  • \(A_1\) записывается, только если \(n\ge2\).

Реализация

Замечания к реализации

Не хватает стандартных заголовков

Код использует:

  • int64_t;
  • rand;
  • std::swap.

Для переносимой программы соответствующие объявления следует получать из явных заголовков:

#include <cstdint>
#include <cstdlib>
#include <utility>

Предпочтительное имя 64-битного типа —

std::int64_t

после подключения <cstdint>.

То, что конкретный компилятор может предоставить эти объявления через транзитивные включения, не является гарантией стандарта C++.

rand() % range не даёт строгой равномерности

Операция

rand() % (right - left + 1)

в общем случае имеет modulo bias, если число возможных результатов rand() не делится на размер диапазона.

Кроме того, стандарт C++ гарантирует только

\[ \texttt{RAND\_MAX}\ge32767. \]

На реализации с малым RAND_MAX не все смещения большого диапазона вообще могут быть выбраны одним вызовом rand().

Это не нарушает логическую корректность partition: любой pivot допустим. Однако это не позволяет использовать модель «равномерно случайный pivot» без дополнительного обоснования ожидаемой сложности.

Отсутствие srand не доказывает требуемую детерминированность

Если srand не вызывался, реализация rand() начинает с заданного начального состояния. Это может делать последовательность воспроизводимой в рамках одной стандартной библиотеки.

Но бонус требует не просто повторяемого выполнения, а детерминированного алгоритма с гарантией \(O(n)\). Даже если считать данную последовательность pivot детерминированной, контрпример со всеми нулями всё равно даёт \(\Theta(n^2)\).

Рекурсию можно заменить циклом, но этого недостаточно

QuickSelect естественно реализуется итеративно, изменяя left или right. Это устраняет риск линейного расхода стека.

Однако итеративная форма не меняет сумму размеров обработанных диапазонов. Без гарантированно хорошего pivot худшее время остаётся квадратичным.

Проверка

Граничные случаи

  • \(n=1\): ответ равен \(A_0\); текущий код имеет выход за границу массива.
  • \(k=1\): требуется минимум массива.
  • \(k=n\): требуется максимум массива.
  • \(A_0=A_1=0\): весь массив состоит из нулей.
  • Все значения равны: двухчастное partition не должно рекурсивно удалять по одному элементу.
  • Много дубликатов: нужен отдельный блок == pivot.
  • Pivot является минимумом или максимумом: одна из строгих частей пуста.
  • Уже отсортированный или обратно отсортированный массив: фиксированный неудачный pivot может дать квадратичное время.
  • Равные значения по обе стороны выбранной позиции: порядковая статистика определяется значением, а не уникальным исходным индексом.
  • \(k\) во входе нумеруется с единицы, внутренний индекс — с нуля.
  • \(n=10^7\): необходимо учитывать реальный объём массива и глубину стека.

Failure mode

Главный failure mode

Главная ошибка — смешение двух разных утверждений:

QuickSelect часто работает за линейное время.

и

Данная реализация гарантированно работает за \(O(n)\) на всех допустимых входах.

Первое утверждение может быть верным как ожидаемая оценка для подходящей randomized-реализации. Второе для переданного кода ложно.

Особенно важно не забывать о дубликатах. В этой задаче они не являются редким или искусственным случаем: рекуррентная генерация допускает массив из одинаковых нулей.

Правильная последовательность проверки:

  1. доказать свойства partition;
  2. доказать уменьшение области поиска;
  3. отдельно оценить, насколько уменьшается область;
  4. проверить дубликаты;
  5. определить вид оценки: худшая, ожидаемая или амортизированная.

Корректность ответа сама по себе не даёт требуемой временной гарантии.

Перенос идеи

Признаки похожих задач

Selection стоит рассматривать, когда:

  • требуется только \(k\)-й элемент, а не весь отсортированный массив;
  • после partition можно навсегда отбросить одну часть;
  • ответ зависит от ранга элемента;
  • полная сортировка за \(O(n\log n)\) выполняет лишнюю работу.

Трёхчастное partition особенно важно, когда:

  • значения могут повторяться;
  • диапазон значений мал;
  • вход генерируется по модулю;
  • известны тесты с большим числом одинаковых ключей.

Median of medians нужен, когда одновременно требуются:

  • детерминированность;
  • линейное время именно в худшем случае;
  • независимость гарантии от распределения входных данных.

Отдельный сигнал этой задачи — небольшой известный диапазон значений. Он позволяет также проверить frequency/counting-подход с оценкой \(O(n+M)\).
