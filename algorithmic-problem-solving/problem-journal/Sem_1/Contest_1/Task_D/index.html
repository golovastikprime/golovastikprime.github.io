Задача D — LSD radix sort для uint64_t

Accepted · C++ · 23 июля 2026

Устойчивость принципиальна: внутри группы с одинаковым текущим байтом должен сохраняться уже построенный порядок по всем младшим байтам.

Условие

Условие

Дан массив из \(n\) неотрицательных 64-битных целых чисел:

\[ 1\le n\le 10^6, \qquad 0\le a_i<2^{64}. \]

Требуется отсортировать массив по неубыванию, реализовав поразрядную сортировку LSD.

Каждое число помещается в uint64_t; максимально допустимое значение равно \(2^{64}-1\).

Подход

Ключевое наблюдение

У каждого 64-битного числа есть ровно восемь 8-битных разрядов. Если выбрать основание

\[ B=2^8=256, \]

то любое входное число \(x\) единственным образом представляется как

\[ x=d_0+d_1B+d_2B^2+\cdots+d_7B^7, \qquad 0\le d_i<256. \]

Разряд \(d_0\) — младший байт, а \(d_7\) — старший.

Его можно извлечь битовыми операциями:

\[ d_i(x)= \left(x\mathbin{\texttt{>>}}(8i)\right) \mathbin{\texttt{\&}}255. \]

Алгоритм LSD обрабатывает разряды от младшего к старшему:

\[ d_0,d_1,\ldots,d_7. \]

На каждом проходе массив устойчиво сортируется по одному байту с помощью counting sort.

Устойчивость здесь принципиальна: когда элементы с одинаковым текущим байтом сохраняют взаимный порядок, сохраняется уже построенный порядок по всем младшим байтам.

Основание

Почему основание равно 256

Для одного байта существует только \(256\) возможных значений. Поэтому один проход counting sort занимает

\[ \Theta(n+256) \]

времени и не использует сравнения элементов.

Для 64-битного ключа требуется ровно

\[ \frac{64}{8}=8 \]

проходов. Число проходов и размер алфавита разрядов являются константами, поэтому полная сортировка работает за линейное время относительно \(n\).

В общем случае при разряде ширины \(r\) бит число проходов равно \(\lceil64/r\rceil\), а стоимость имеет вид

\[ O\left( \left\lceil\frac{64}{r}\right\rceil \cdot(n+2^r) \right). \]

Выбор \(r=8\) даёт небольшой массив счётчиков и всего восемь проходов.

Алгоритм

Алгоритм

Создаётся вспомогательный массив buffer длины \(n\).

Для каждого номера байта

\[ b=0,1,\ldots,7 \]

выполняются следующие действия.

  1. Создать массив count[256], заполненный нулями.
  2. Для каждого числа \(x\) извлечь текущий байт
    \[ d_b(x)=(x>>(8b))\mathbin{\&}255 \]
    и увеличить count[d_b(x)].
  3. Вычислить начала блоков:
    \[ \operatorname{pos}[0]=0, \qquad \operatorname{pos}[d] = \sum_{j=0}^{d-1}\operatorname{count}[j]. \]
  4. Ещё раз просмотреть текущий массив слева направо. Число с байтом \(d\) записать в buffer[pos[d]], после чего увеличить pos[d].
  5. Обменять nums и buffer.

После восьмого прохода nums содержит окончательно отсортированный массив.

Корректность

Корректность одного прохода counting sort

Рассмотрим фиксированный байт \(b\).

После подсчёта count[d] равно числу элементов с текущим байтом \(d\). Следовательно,

\[ \operatorname{start}[d] = \sum_{j<d}\operatorname{count}[j] \]

является индексом начала блока элементов с байтом \(d\) в выходном массиве.

Массив pos сначала содержит эти начала. При записи очередного элемента с байтом \(d\), pos[d] указывает на первую ещё не занятую позицию его блока. После записи указатель увеличивается.

Отсюда следуют два свойства.

Сортировка по текущему байту

Блок байта \(0\) расположен раньше блока байта \(1\), блок байта \(1\) — раньше блока байта \(2\), и так далее. Поэтому выходной массив отсортирован по \(d_b\).

Устойчивость

Исходный массив просматривается слева направо. Два элемента с одинаковым байтом \(d\) записываются в последовательные позиции одного блока в том же порядке, в котором были встречены.

Следовательно, один реализованный проход является устойчивой сортировкой по текущему байту.

Инвариант

Инвариант LSD

Для \(t\in\{1,\ldots,8\}\) определим младший \(t\)-байтовый ключ:

\[ K_t(x)=x\bmod 256^t. \]

После завершения первых \(t\) проходов массив отсортирован по неубыванию \(K_t(x)\).

Иными словами, после обработки байтов

\[ d_0,d_1,\ldots,d_{t-1} \]

элементы расположены в правильном порядке по числу, составленному из этих байтов.

База: \(t=1\)

Первый проход устойчиво сортирует массив по младшему байту \(d_0\). Но

\[ K_1(x)=x\bmod256=d_0(x), \]

поэтому инвариант выполнен.

Индукционный переход

Предположим, после \(t\) проходов массив отсортирован по \(K_t\). На следующем проходе выполняется устойчивая сортировка по байту \(d_t\).

При этом

\[ K_{t+1}(x) = d_t(x)\cdot256^t+K_t(x). \]

Рассмотрим два элемента \(x\) и \(y\).

  • Если \(d_t(x)<d_t(y)\), то новый counting sort помещает \(x\) раньше \(y\). Это совпадает с порядком их ключей \(K_{t+1}\), поскольку текущий байт является старшей частью этих ключей.
  • Если \(d_t(x)=d_t(y)\), то устойчивость сохраняет прежний взаимный порядок \(x\) и \(y\). По индукционному предположению этот порядок уже является порядком по младшей части \(K_t\).

Следовательно, после нового прохода массив отсортирован по \(K_{t+1}\). Инвариант доказан по индукции.

Доказательство

Доказательство корректности всей сортировки

После восьми проходов из инварианта следует, что массив отсортирован по ключу

\[ K_8(x)=x\bmod256^8=x\bmod2^{64}. \]

Для каждого допустимого входного числа

\[ 0\le x<2^{64}, \]

поэтому

\[ x\bmod2^{64}=x. \]

Значит, порядок по \(K_8\) совпадает с обычным числовым порядком значений uint64_t. Следовательно, алгоритм выводит исходные элементы в порядке неубывания.

Алгоритм только переставляет элементы и на каждом проходе записывает каждый из них ровно один раз. Поэтому ни одно значение не теряется и не добавляется: результат является перестановкой исходного массива.

Устойчивость

Почему сортировка должна быть устойчивой

После обработки младших байтов их порядок должен сохраняться внутри группы элементов с одинаковым следующим байтом.

Например, рассмотрим два числа:

\[ 256=(01\,00)_{16}, \qquad 257=(01\,01)_{16}. \]

После сортировки по младшему байту правильный порядок равен

\[ 256,\ 257. \]

Их следующий байт одинаков и равен \(1\). Если сортировка по этому байту поменяет равные элементы местами, получится

\[ 257,\ 256, \]

и уже достигнутый порядок по младшему байту будет разрушен.

Текущая реализация избегает этой ошибки: элементы читаются из nums слева направо и помещаются в очередную свободную позицию своего блока.

Оценка

Сложность

Один байтовый проход выполняет:

  • \(\Theta(n)\) операций для подсчёта цифр;
  • \(\Theta(256)\) операций для вычисления начал блоков;
  • \(\Theta(n)\) операций для устойчивого распределения.

Поэтому его стоимость равна

\[ \Theta(n+256). \]

Проходов ровно восемь:

\[ T(n)=8\Theta(n+256). \]

Так как \(8\) и \(256\) — константы, при \(n\ge1\)

\[ \boxed{T(n)=\Theta(n)}. \]

Это худшая, а не ожидаемая оценка: расположение входных элементов не меняет число проходов и число обработанных элементов.

Вспомогательный buffer содержит \(n\) значений uint64_t, а массивы count и pos содержат по \(256\) целых чисел. Дополнительная память равна

\[ 8n+O(256)\text{ байт} \]

без учёта служебных данных vector, то есть асимптотически

\[ \boxed{O(n)}. \]

Вместе с исходным массивом одновременно хранится примерно \(16n\) байт данных чисел: при \(n=10^6\) это около \(16\) MB.

Проверка

Граничные случаи

  • Один элемент: каждый проход переписывает его в позицию \(0\).
  • Все элементы равны: стабильность сохраняет их порядок, значения остаются неизменными.
  • Все числа равны нулю: каждый байт каждого числа равен нулю.
  • Максимальное значение:
    \[ 2^{64}-1, \]
    у которого все восемь байтов равны \(255\).
  • Числа отличаются только старшим байтом: правильный порядок устанавливается на последнем проходе.
  • Числа отличаются только младшим байтом: порядок устанавливается на первом проходе и сохраняется всеми последующими.
  • Дубликаты: они не требуют специальной обработки.
  • Уже отсортированный и обратно отсортированный массивы: время остаётся \(\Theta(n)\).

Безопасность

Безопасность целочисленных операций

Все битовые операции выполняются над беззнаковым типом uint64_t.

  • Максимальный сдвиг равен
    \[ 8\cdot7=56<64, \]
    поэтому правый сдвиг определён.
  • Маска 255 оставляет ровно младшие восемь бит после сдвига.
  • Извлечённый разряд всегда лежит в диапазоне \([0,255]\), поэтому является корректным индексом массива размера \(256\).
  • Значения count[d] и pos[d] не превосходят \(n\le10^6\), поэтому помещаются в int.
  • Над самими входными числами не выполняются сложение или умножение, которые могли бы вызвать переполнение.

Таким образом, значение \(2^{64}-1\) обрабатывается так же корректно, как любое другое допустимое число.

Буфер

Почему buffer не нужно очищать

На каждом проходе блоки всех \(256\) значений байта:

\[ [0,\operatorname{count}[0]), \quad [\operatorname{count}[0], \operatorname{count}[0]+\operatorname{count}[1]), \quad\ldots \]

попарно не пересекаются и вместе покрывают весь диапазон индексов \([0,n)\).

Каждый входной элемент записывается ровно в одну позицию соответствующего блока. Поэтому все \(n\) ячеек buffer перезаписываются на каждом проходе, и старое содержимое после nums.swap(buffer) не влияет на следующий проход.

Реализация

Замечания к реализации

Вычисление сдвига

В коде используется:

const int cKBytes = 8;
int shift = cKBytes * byte;

Результат численно правилен: сдвиги равны

\[ 0,8,16,\ldots,56. \]

Однако одна и та же константа одновременно интерпретируется как число 8-битных разрядов и как число бит в одном разряде. Эти величины равны восьми только случайно.

Семантически точнее разделить их:

constexpr int cDigitCount = 8;
constexpr int cBitsPerDigit = 8;
int shift = cBitsPerDigit * digit_index;

Это clarification, а не ошибка результата текущей программы.

Имена констант

Названия cKBase и cKBytes затрудняют чтение: буква K не добавляет семантики. Более точные имена:

cBase
cDigitCount
cBitsPerDigit

Квалификация типа

После подключения <cstdint> переносимая C++-форма имени имеет вид std::uint64_t. На используемой платформе неквалифицированное uint64_t доступно и код компилируется, но явная квалификация лучше показывает источник типа.

Типы индексов

При ограничении \(n\le10^6\) тип int достаточен для count, pos и индексов входного массива. Переход на std::size_t здесь не требуется для корректности, хотя может быть полезен в переиспользуемой библиотечной версии.

Функциональных ошибок не найдено

При ограничениях из условия все восемь байтов обрабатываются, counting sort является устойчивой, индексы остаются допустимыми, а итоговая сложность линейна. Замечания выше относятся к ясности и переносимости, но не меняют результат решения.

Failure mode

Главный failure mode

Личный тупик до Accepted не был описан, поэтому он не приписывается автору. Главная логическая опасность LSD radix sort — реализовать неустойчивый внутренний проход.

Сам факт, что после очередного counting sort элементы сгруппированы по текущему байту, недостаточен. Необходимо также доказать, что внутри каждой группы сохранён порядок по уже обработанным младшим байтам.

Вторая частая ошибка — обработать байты в обратном порядке. Проход от старшего байта к младшему с тем же простым последовательным алгоритмом оставит младший байт главным ключом. Для LSD порядок проходов обязан быть

\[ \text{младший}\longrightarrow\text{старший}. \]

Сравнение

Почему близкие подходы здесь хуже

Сортировка сравнениями

std::sort, merge sort и heap sort требуют

\[ \Omega(n\log n) \]

сравнений в общей модели сортировки сравнениями. Они не используют тот факт, что ключ имеет фиксированную длину \(64\) бита и разбивается на разряды из малого алфавита.

Кроме того, условие прямо требует реализовать LSD radix sort.

Counting sort по всему значению

Диапазон ключей имеет размер

\[ 2^{64}. \]

Массив счётчиков такого размера невозможен. Radix sort заменяет один огромный алфавит восемью проходами по алфавиту размера \(256\).

MSD radix sort

Сортировка от старшего разряда также возможна, но обычно требует рекурсивно разбивать массив на группы и отдельно обрабатывать каждую группу. Для фиксированных 64-битных чисел итеративный LSD-вариант проще: достаточно одного буфера и восьми одинаковых устойчивых проходов.

Перенос идеи

Признаки похожих задач

LSD radix sort стоит рассматривать, когда:

  • ключи имеют фиксированную небольшую битовую длину;
  • значения целые и их разряды можно извлечь за \(O(1)\);
  • алфавит одного разряда мал;
  • требуется сортировка большого массива быстрее общей \(O(n\log n)\)-сортировки сравнением;
  • доступна линейная дополнительная память;
  • можно реализовать устойчивую сортировку по одному разряду.

Перед применением необходимо уточнить:

  • числа знаковые или беззнаковые;
  • сколько разрядов нужно обработать;
  • каков порядок разрядов;
  • является ли внутренний проход устойчивым;
  • помещается ли массив счётчиков выбранного основания в память.

Для знаковых целых обычный беззнаковый порядок битов не совпадает с числовым порядком: знаковый разряд требует отдельной обработки. В текущей задаче все числа неотрицательны и хранятся в uint64_t, поэтому этой проблемы нет.
